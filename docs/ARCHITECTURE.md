# Architecture Notes

## Integration boundary (0.27.0)

Anglefeint is a static Astro publishing theme distributed as a thin starter plus `@anglefeint/astro-theme`. Code defines implemented behavior; this reference follows it. Version 0.27.0 introduced the breaking starter transition. See [migration](../UPGRADING.md#0270-integration-starter-breaking-not-yet-published), its [delivery record](releases/0.27.0.md), and the optional compatible [0.28.0 feature](releases/0.28.0.md).

The consumer owns articles, assets, music/images, site-config values, custom pages and deployment secrets/settings. The package owns standard pages, defaults/types, configuration/i18n resolution, styles/effects, build integrations and CLI. A normal feature update changes the package instead of asking authors to merge page implementations. The repository root is also the maintainer demo; old root config/i18n adapters remain diagnostic compatibility fixtures, not distributed application dependencies. New starters do not receive them.

## Entrypoints and configuration

- `astro.config.mjs` calls `anglefeint(THEME_CONFIG)` from the package integration. `packages/theme/src/integration.mjs` sets aliases and registers the standard route/build integrations.
- `src/site.config.ts` contains user settings. New starters import `defineThemeConfig` and types from `@anglefeint/astro-theme/config`; the package's `project/defaults.ts`, `schema.ts` and `runtime.ts` implement defaults, deep merge and locale normalization. Objects merge recursively, undefined overrides are skipped, arrays replace whole arrays, and explicit empty strings/lists retain their existing field-specific meanings.
- `project/config/*` derives site, feature, About and social settings; `project/i18n/*` derives runtime paths, messages and sorted post selection. `@anglefeint/user-config` resolves the actual site file. `@anglefeint/site-config/*` and `@anglefeint/site-i18n/*` are integration-provided imports for theme/custom pages; the starter extends `@anglefeint/astro-theme/tsconfig` and uses injected package env types, so authors do not maintain internal directory mappings.
- The existing site-config values remain valid, including all music tracks and locale overrides. The schema/default runtime implementation is no longer copied into consumer projects. The demo's helper entry files forward to the package so its existing site-config bytes are preserved.
- PUBLIC_SITE_URL and other existing PUBLIC_SITE_* identity overrides retain precedence. `project/site-url.mjs` uses the CLI dotenv mode before Astro resolves site; Vite later supplies page runtime metadata. The integration resolves matching title/description values for machine exports. Configuration changes require rebuild/deploy.

## Static routes and content

`integration.mjs` registers package-owned files in `routes/`: `/`, robots.txt, localized Home, Blog pagination, article slugs, Tags/index archives, About, Decoder, RSS and terminal JSON. Existing getStaticPaths/content queries are preserved. Custom project pages still live in src/pages outside these paths. A copied standard route is rejected with migration guidance; `new-page` reserves standard path prefixes instead of creating collisions. The demo's development-only player preview remains project-owned and emits no production route.

`content-schema.ts` uses Astro's glob loader over the consumer's `src/content/blog/**/*.{md,mdx}`. Required frontmatter is title, description and pubDate. Optional image, author, tags, TOC/search, updatedDate, source/context and AI-stat fields retain their current validation. No draft or future-date filter is introduced. Posts are filtered by locale ID and sorted by publication date. Related articles remain within the current locale. `utils/metrics.ts` derives estimates from source text, respecting explicit overrides; these are not real AI usage or confidence measurements.

Default locale prefix mode affects Home only: always gives a root meta-refresh/noindex/canonical page; never renders the default Home at root and redirects its localized duplicate. Blog/article URLs remain localized. Configured locales, labels, hreflang/OG codes, enablement and fallback behavior come from project/i18n. Nine built-ins remain enabled by default; custom locale choices are user settings. Matching article slugs define real translations; missing translations remain menu fallbacks to archives and are omitted from article SEO alternates.

## Article statistics

`utils/metrics.ts` removes fenced/inline code, HTML, images and Markdown links, strips selected Markdown markers and collapses whitespace. CJK Han/Hiragana/Katakana/Hangul characters count individually; remaining text uses whitespace-delimited words. Math/MDX source is not specially excluded. For `safeWords = max(words, 1)`, defaults are `max(1, ceil(safeWords / 220))` minutes, `round(safeWords * 1.3)` tokens, `round(140 + min(safeWords, 2800) * 0.11)` estimated latency, and `min(0.98, 0.78 + log10(max(safeWords, 20)) * 0.04)` confidence rounded to two decimals. Explicit frontmatter overrides each field independently; overriding wordCount does not recalculate other estimates. These are deterministic presentation estimates, not model tokenization, actual AI timing or verified confidence.

## Composition and visual systems

`effects/` holds reusable visuals within the existing theme package: Matrix rain, signal loading, Cyber spotlight, white rabbit, Cyber rain/dust, article AI backdrop, SVG network backdrop and Red Queen monitor. Their renderers accept supplied roots/canvases and explicit inputs; Astro components own visual markup/styles. Homepage, CyberShell/atmosphere and comment/article adapters retain page selectors, layout, scene variants, configuration, labels and startup policy. Article AI and Decoder SVG networks are separate implementations with different rendering contracts; no runtime switch or combined renderer is introduced. Red Queen includes its play button, frame and player, while article assets/labels, gutter positioning and autoplay remain caller-owned.

See [Reusable effects](REUSABLE_EFFECTS.md) for APIs and the source map. Existing public component/script paths remain thin compatibility entries; old article-network/Red-Queen adapters preserve phased startup and existing lifecycle scopes. The shared resource helper remains at `scripts/effects/lifecycle.js`; it is not a second visual implementation.

Standalone key buttons, blink cursors, configurable startup text, hidden signals and Cyber environment layers now live under `effects/key-button`, `blink-cursor`, `startup-text`, `hidden-signal` and `cyber-environment`. Each has an Astro view and explicit DOM binding; startup SSR/client bindings share one pure model. Home retains its flags, text/layout and post-unlock preview policy, while CyberShell/atmosphere retain scene composition and palette overrides. These reusable effects import no mirror/3D-passage implementation. The mirror and corridor remain their existing scene-specific/shared modules; no further generalization is implied.

`components/shared/ThemeFrame.astro` owns shared HTML/head/header/footer/music composition. Base/Ai/Cyber/Hacker/Matrix shells choose body classes, styles and background hooks; reusable page layouts support custom pages. `routes/*`, HomePage and BlogPost compose data and presentation together inside the package. `components/CyberAtmosphere.astro` and `scripts/cyber-rain-dust.js` now ship in the package without effect changes.

The four cinematic identities, palettes, animation parameters, responsive layouts and accessibility/reduced-motion behavior are preserved. This migration changes ownership, not visual design. [Visual Systems](VISUAL_SYSTEMS.md) records appearance/effect contracts. `scripts/effects/lifecycle.js` scopes optional effect resources and reverse cleanup. Home coordinates shared rain/mirror/rabbit/passage lifetimes; About coordinates window controls, terminal, modals, Oracle and an independent decoder clock; article effects return disposers and cancel deferred starts, with cached-page visibility recovery. No new client router or seamless-audio promise is introduced.

About retains localized contents/contact anchors, window close/minimize/fullscreen commands and local preferences. The read-only terminal keeps filesystem/commands/session/loader/Canvas renderer separate from About. Virtual paths are inert JSON/text; same-origin localized terminal JSON provides public article text on demand. Decoder Lab and About use shared codecs, bounded history/actions and numeric reveal; crypto stays lazy/local with no RPC/wallet/chain-state lookup. `theme.enableAboutPage` and `enableDecoderPage` remain independent route/navigation gates.

<a id="optional-music-player"></a>

Music remains optional/default-off with a nonempty playlist. Native audio core, tab-session storage and page-specific skins remain separate; source-based track identity, manual pause, seekable blobs, resume intent and browser autoplay/CORS limits are unchanged. The updater never manages audio files. User social links and rel/iconSrc rules keep existing static validation, ordering and safe rel tokens.

## Build integrations and SEO

Since 0.33.0, optional `site.ogImage` in `project/schema.ts` / `defaults.ts` accepts a public-root path or HTTPS URL (blank by default). `BaseHead.astro` resolves it through `social/resolve.mjs` only when the page supplies no image. The bundled default is `assets/theme/social/anglefeint-og.jpg` (1200×630). Public overrides receive byte-revision queries; missing files fail the build. OG, Twitter and JSON-LD use the same URL. Fragment anchors do not create distinct metadata. Article explicit/generated images and disabled-generation heroes retain priority. The existing social integration provides the public directory; no second image service or frontend script is added.

The unified integration supplies MDX, the existing build-time Satteri/KaTeX Markdown processor, social-image endpoints, machine-readable exports, Pagefind and sitemap. Users should not also add the former standalone integrations to the same project. Custom unrelated integrations remain allowed. No production Node process is needed; publish all of dist/.

- `BaseHead.astro` and `utils/head.ts` provide canonical, article/WebSite/Person JSON-LD, Open Graph/Twitter and RSS discovery. `utils/article-locales.ts` discovers only enabled existing translations, with explicit SEO maps authoritative (including empty maps). Tag routes omit hreflang but retain menu language links and self-canonical. Author links appear only for the configured site author when About is enabled.
- `sitemap.mjs` wraps @astrojs/sitemap URL discovery, retaining the Home redirect filter. It reads rendered article metadata and adds lastmod from article:modified_time then article:published_time (updatedDate ?? pubDate). Non-articles and missing/invalid dates receive no invented timestamp. No filesystem/build time is used.
- Standard robots allows crawling and advertises the same-origin sitemap index. Production player-preview routes are absent. JSON, RSS, social PNGs and Markdown companions are not ordinary page sitemap entries.
- Terminal JSON sets X-Robots-Tag: noindex at its route. Static responses additionally need host metadata: the integration merges `/:locale/terminal/*` into built dist/_headers, preserving user host rules and not writing public/_headers. Cloudflare Pages/compatible hosts apply it; other platforms need equivalent configuration. Robots remains open so the crawler can read noindex. Astro preview does not enforce host header files.
- The package About-runtime validator checks built href/src/action URL attributes against the configured virtual cwd/file paths. It does not create routes for historical crawler discoveries or redirect removed template pages.
- Pagefind indexes only opted-in article content, by page language; zero-article and disabled search remain empty/off. Pagefind is the third-party npm dependency that generates indexes and supplies the browser search engine. Both the previous `index.writeFiles()` call and current `index.getFiles()` call use its public API. We have not modified dependency source, introduced a fork or accessed private native functions; our integration owns configuration/filtering and the completed file-output handoff. The build integration obtains complete buffers with `index.getFiles()` and awaits Node writes for every returned file before publishing `anglefeint.json` and completing the hook. Metadata comes from the returned entry bytes, not an immediate read of native disk output. This avoids Pagefind 1.5.2's native write-completion race; failures still stop the build. Buffers temporarily occupy build-process memory proportional to the index bundle, without adding browser payload or changing search URLs. Assumptions about returned file paths and generated `pagefind-entry.json` language metadata remain localized in `search.mjs` and covered by `tests/search.test.mjs`; the browser wrapper in `scripts/search.js` lazily imports the generated engine and invokes its public search interface. TOC uses compiler headings, while copy/preview/progress interactions retain no-JavaScript reading and keyboard behavior.
  <a id="article-share-images"></a>

- Social images use offline fonts/assets with Satori/Sharp, metadata-keyed caching and explicit ogImage precedence. The integration externalizes its own pure-Node renderer to a package-local file URL so pnpm isolation cannot bundle Yoga glue or lose native dependency resolution. PNG optimization remains lossless; body font delivery is unchanged.
- Machine-readable exports use explicit rendered-page adapters in `machine/content.mjs`: article body/metadata, About public biography/contact plus the reachable AI text popup, and Fragment cards (ID/time/body). About's runtime JSON is read only for its allowlisted AI popup, never terminal entries, effects or arbitrary configuration. UI/comments/tools are excluded. `machine/generate.mjs` merges public Fragment pages into one `/<locale>/fragments/index.md`, preserving root `#ID` share links and date-descending/ID ordering; the public feed root must exist, so pagination cannot bypass a noindex/missing root. About uses `/<locale>/about/index.md`; article addresses remain unchanged. Root indexes discover languages; language indexes separate Articles/Fragments/About, and full-text bundles include all supported content. Each eligible HTML page advertises its companion and language index (all feed pages share the aggregate).
- Exports respect noindex/off-site canonical and exist only for rendered enabled routes/languages. Existing adapters preserve MDX/code/math and absolute destinations. Global/locale aiReadableContent supplements inherit per field with explicit empty suppression and apply to every companion; bundles include the site supplement once. The single ownership manifest protects user files, rejects conflicts/duplicate Fragment IDs, removes stale companions/indexes/bundles and strips stale owned HTML discovery links. No new runtime script/server/dependency is added. Site/article JSON-LD includes configured hreflang language, and About adds AboutPage with language. These facilities do not guarantee AI citations or search indexing.

## Upgrade contract and distribution

Consumers carry `anglefeint.projectSchema: 1` in package.json. `npx @anglefeint/astro-theme@latest upgrade` invokes the package's astro-theme bin (npm resolves its name-matching binary). It requires an npm package-lock.json for recoverable installation and checks project/lockfile family, target name/version/schema, Node and installed Astro compatibility, then backs up dependency files, installs the exact target with lifecycle scripts disabled and runs doctor. User source/config/media are not rewritten. Failure restores dependency files and attempts old-dependency reinstall; incomplete recovery reports the backup path. Same-schema skipped versions work; unknown schema/Node/Astro changes stop for deliberate migration. No cross-schema migration or automatic deployment is implemented. npm is the supported automatic manager; others are refused rather than silently converted.

Old copied skeletons intentionally require one fresh-starter migration. Deep custom standard-page replacements are not silently merged. Future public defaults/features should stay behind this integration boundary; a compatible release must not assume a user manually applied an intermediate starter patch.

The reserved-route guard compares supported source-page URLs, including Markdown/MDX, index aliases, concrete enabled-locale folders, renamed dynamic language parameters and JSON endpoints, rather than checking only old .astro filenames. A conflict stops with the original file retained. Independent custom URLs remain supported. Dependency rollback does not restore dist/: a failed build requires a successful doctor/rebuild before deployment; the CLI states this explicitly.

`scripts/starter-manifest.mjs` is maintainer-only distribution metadata. It manages the thin entry files, neutral site-config source, guidance/docs, whitelisted sample posts and their required cover/font assets. It removes obsolete generated files only in the maintainer's distribution branch; upgradeProject never invokes this sync or its deletion list. `starter-package.mjs` distributes only Astro/theme runtime dependencies, check/TypeScript dev tools and package-owned commands. Packaging must include routes/project/runtime/CLI implementations. Root maintainer tooling and tests are not consumer dependencies.

## Article comments

`project/schema.ts` and `project/defaults.ts` define `theme.comments.shareAcrossLocales` (default false). `utils/comments.ts` validates configuration through `project/config/theme.ts` (also reused by the maintainer adapter fixture). Disabled comments keep deferred configuration validation. Ordinary mapping, term, number, strict and language defaults are unchanged.

Opt-in sharing requires mapping specific, empty term/number and strict 1. Conflicts fail while comments are enabled rather than replacing user choices. The standard article route computes `blogIdToSlugAnyLocale(post.id)` and passes `articleSlug` to `layouts/BlogPost.astro`; `articleComments` creates local Giscus parameters using that complete slug, preserving directories. Missing/invalid slugs fail explicitly. Custom article layouts using BlogPost must also pass an articleSlug when sharing is enabled. The global configuration is never mutated.

`components/Giscus.astro` continues to emit the official public client script. Shared mode uses specific mapping, the per-article term and strict matching; ordinary mode retains its configured mapping. Explicit lang wins, otherwise the existing locale mapping follows the page. Identical translation slugs share a discussion and reactions in shared mode, not translated comment text. No GitHub merge/delete calls or third-party source changes are introduced. `tests/comments.test.mjs`, `tests/project-config.test.mjs` and `tests/comments-render.test.mjs` cover validation, defaults and final nine-language HTML, including nested slugs and ordinary custom mappings.

The dedicated nine-language `starter-guide-4-giscus-comments` tutorial is maintained in demo content and starter overrides, registered in `scripts/starter-manifest.mjs`; Guide 3 links to it. Personal consumer posts/configuration remain outside upgrade writes.

## Fragments (optional short-form publishing)

Articles and Fragments compose `components/shared/BackToTop.astro`, which owns `scripts/back-to-top.js` and `styles/back-to-top.css`. The controller binds explicit button elements, disposes page listeners and responds to scroll/resize without an animation loop. Article reading progress remains article-owned; Fragments does not import article effects. The feed selects its own positioning preset and reuses the existing localized article label.

Since 0.33.0, `scaffold/new-fragment.mjs` calls CLI-only `scaffold/fragment-id.mjs`: Nano ID 5 generates eight case-sensitive alphanumeric characters, YAML frontmatter supplies existing IDs across all language/nested Markdown directories, and collisions retry at most twenty times before failing without writing files. Generated IDs are quoted to preserve numeric strings. Nano ID and js-yaml are explicit package dependencies, not browser imports. One invocation shares ID/time across selected locales. The schema, link client and comment terms accept exactly eight ASCII letters/digits. UUIDs and long IDs are rejected; no migration state, aliases or old-link redirects are provided.

Fragments uses the same `components/pagination/CyberPagination.astro` and `utils/pagination.ts#buildPaginationModel` as Blog and tag archives. It supplies its localized feed root through the existing `blogRoot` prop, generic pagination labels from `messages.blog` and existing `THEME.PAGINATION` settings; `theme.fragments.pageSize` remains independent. The shared component owns numbered links, ellipses, neon variants and the threshold-based jump control. Fragment-specific pagination markup/CSS is removed; `fragment-index.ts` and `fragment-links.js` still own exactly the same page mapping and stable sharing behavior.

Sharing: dates expose `/<locale>/fragments/#ID` and adjacent copy controls use the same stable root-feed URL. Card DOM IDs use the content ID directly, without a `fragment-` prefix. Normal clicks on an already-present card keep the current page and update its hash; the real href still supports native opening/copying. There are no detail pages. Numbered browser addresses remain browsing locations, not canonical sharing links. Comment terms retain their independent `fragment/ID` namespace; no legacy prefixed-anchor alias is added.

`utils/fragment-index.ts#buildFragmentIndex` is build-only and owns the shared sorting/pagination calculation for the feed and `routes/[lang]/fragments/index/[revision].json.ts`. It emits version 1, totalPages and an ID→page map per enabled language; its SHA-256 content revision names the static JSON. Feed HTML carries only that URL, page/root metadata and localized labels, never the full index or all Markdown. `scripts/fragment-links.js` checks the current card first, fetches only missing targets, deduplicates requests and ignores obsolete responses. Index URLs are excluded from sitemap output. No database, site-config field or dependency is introduced; the conditional integration owns the endpoint, not starter files.

The client handles initialization/hash changes/history, copying with selectable-input fallback, missing IDs and load errors. A short-lived `_fragment_jump` query carries a one-hop arrival guard across navigation and is removed immediately; copied links never contain it. Same-page index inconsistencies and missing destinations report refresh feedback instead of looping, including when browser storage is unavailable. A versioned filename prevents new HTML from using a cached index of another revision; old cached HTML referencing a removed asset may still need a refresh. Pagehide aborts requests/listeners/timers; cached-page restore rebinds. No frame loop/observer or per-card event listeners are added. JavaScript-disabled pages retain reading/native date links, with copy controls hidden. A removed numbered page keeps its host's normal 404; there is no 404 interceptor. Existing Giscus IDs/terms and retained-dialog behavior are unchanged.

Sharing validation: `tests/fragment-index.test.mjs` covers language isolation, re-pagination, filename changes/deletion and content revisions. `tests/fragments-render.test.mjs` checks actual static JSON, all nine languages, stable hrefs after pageSize changes and disappearing numbered pages. `tests/e2e/fragments.spec.mjs` checks on-demand lookup, same-page navigation/copying, errors, stale responses, one-hop protection, clipboard fallback and comment regressions. New runtime files are required by `scripts/check-theme-pack-cli.mjs`; README and nine demo/starter Guide 5 pairs describe the publication/JavaScript/404 boundaries.

`theme.fragments` is package-owned: `{ enabled: false, pageSize: 20, comments: { enabled: false } }`. `pageSize` is an integer from 1 to 100. The demo configuration opts into the feed and both article/fragment comments, using its existing Anglefeint Giscus repository/category settings. The starter and omitted configuration stay disabled. The disabled loader does not read fragment files, so unrelated existing content is not newly validated. The integration injects `/<locale>/fragments/` and subsequent numeric pages only when enabled. A custom fragments route is allowed while disabled; enabling with a conflicting custom page fails without replacing it. Locale switches return to the first page because language collections can have different lengths; paginated pages do not advertise misleading hreflang equivalents.

`src/content/fragments/<locale>/**/*.md` is user-owned Markdown, separate from blog articles. Frontmatter requires a stable `id` (exactly eight ASCII letters or digits, case-sensitive) and `pubDate`; `title` is optional. Filename changes do not change discussion identity. IDs must be unique within a language; translations deliberately share an ID. Entries sort by publication instant descending, with ID as tie-breaker; dates display in UTC. There is no draft or future-date publication filter. Each enabled language has its own feed, including an empty state. Fragment Markdown follows the global math setting and loads the existing math stylesheet when enabled. Fragment bodies are not added to article search, RSS, article exports or article social images. The list is included in the normal page sitemap when enabled.

`astro-theme new-fragment [--locales en,zh]` creates exclusive-write Markdown skeletons with one eight-character Nano ID and ISO datetime shared by all files in the invocation. From 0.31.0, the CLI matches `new-post`: `--locales` → `ANGLEFEINT_LOCALES` → all enabled project languages, including the default language. Both use `scaffold/shared.mjs#resolveLocales` for trimming, lowercasing, deduplication and syntax validation; `new-post.mjs` retains its existing re-export. Explicit lists bypass configuration loading and can create valid locale directories without automatically enabling routes. With no override, config failures stop generation before writes. Versions 0.29–0.30 retain the old single-default-language behavior; see the [0.31.0 delivery record](releases/0.31.0.md) for publication and acceptance status. There is no automatic translation. New starters provide `npm run new-fragment`; old npm projects can use the primary package CLI without modifying scripts. The upgrader still changes dependencies only: fragments, articles, config and media remain untouched.

Optional fragment comments reuse `theme.comments.repo/repoId/category/categoryId`, theme, reaction and input-position settings. They do not depend on article `enabled`, `mapping`, `term`, `number`, `strict`, `shareAcrossLocales` or `lang`. They use `specific`, `fragment/<id>`, strict matching and the page language. Missing repository/category fields fail the build when fragment comments are enabled. Existing article discussion associations remain unchanged; no GitHub discussion is merged or removed.

`Giscus.astro` and `utils/comments.ts#giscusConfig` are shared by article and fragment comments: one input contract, repository/category mapping, term/number filtering and locale conversion. Inline article script output retains its existing mapping, strictness, language and loading settings. Deferred fragment output stores the same official `https://giscus.app/client.js` embed in an inert template, with its documented specific/strict/page-language policy. There is no Giscus npm dependency or web-component import.

`FragmentComments.astro` renders one native dialog per feed page. On the first comment click, `scripts/fragment-comments.js` loads that template's client script. The same client and iframe survive closing and switching fragments; public `setConfig` messages change the discussion term. The integration serializes target changes and checks discussion metadata before revealing the frame, preventing a late old response from appearing under another fragment's summary. Session-triggered iframe reloads resynchronize the selected term. The official client owns authentication and iframe creation; the theme owns dialog state, focus/scroll restoration, readiness and retry handling.

Loading remains visible until both iframe load and a Giscus metadata/error message from the expected origin and current iframe arrive. Load alone does not count as success. Script download errors, iframe errors, provider errors and a 15-second timeout show localized feedback and retry; discussion-not-found is a normal empty thread. Retry reloads the existing iframe, or retries the client download if it failed before initialization. Closing hides the retained frame and clears the visible loading state/timer while allowing a late response to be cached. Navigation also disconnects the observer and aborts listeners. A local div heading avoids the site-wide header positioning rules. No private Giscus endpoints, vendor modifications or comment-count scraping are introduced.
