# Template acceptance

Command evidence from `scripts/check-template.mjs` includes ISO `startedAt` and elapsed `seconds` for each consumer command, including expected rejections and failed executions. Dev/preview duration includes readiness, route/browser checks and process teardown; their failure status and timing are retained too. All eleven consumer scripts still execute; timing does not cache or skip any command. npm and pnpm acceptance continue to use separate isolated projects. Maintainer-session input fingerprints are observational context, not acceptance receipts.

`tests/starter-doctor.unit.test.mjs` invokes the real package doctor with a stub npm subprocess to prove Astro check/build execution and build-failure blocking. `tests/starter-sync.unit.test.mjs` verifies the sync ordering and that failed check/audit prevents commit/push. This supports removing only the adjacent duplicate build in maintainer starter sync; it does not replace installed builds or public-template runtime acceptance. `tests/maintainer-session.unit.test.mjs`, `tests/maintainer-evidence.unit.test.mjs` and `tests/verify-release.unit.test.mjs` cover reporting/failure behavior, non-reuse and read-only registry recovery.

Run from the maintainer checkout, not from a user's starter. These tools do not publish, push or alter the real site's configuration. They need network access and installed maintainer dependencies. A passing run covers the recorded scenarios and versions, not every browser, hosting provider or possible user configuration.

## Search output completion

Both `index.writeFiles()` and `index.getFiles()` are public Pagefind APIs. The output-boundary regression below guards our choice of the complete-buffer handoff after observing a version-specific disk-write race; forbidding the old call in this regression does not classify it as a private API. No third-party source or search algorithm is replaced.

`tests/search.test.mjs` verifies that the search hook indexes only opted-in articles and preserves empty/disabled behavior. The output-boundary regression uses complete native-style buffers, including nested binary files, and asserts every byte is readable immediately when `writeSearchIndex` returns. A fake native disk API fails if called; missing/corrupt metadata and native errors must fail rather than fabricate an empty index. Normal full-suite validation uses the existing default parallelism; CPU-affinity restrictions, sleep/retry loops and skipped assertions are not the fix.

For stress diagnosis, isolate each Pagefind service in its own process/output directory, alternate nonempty and zero-article builds, and compare immediate entry reads with subsequent reads. After the fix, repeat the same workload using the memory-to-awaited-write boundary, verify complete output bytes and run the normal full suite. Native Pagefind files are still generated by Pagefind; the theme only owns their awaited filesystem handoff. Exact dated results belong in the code/document audit, not a claim that an unpublished patch has reached users.
