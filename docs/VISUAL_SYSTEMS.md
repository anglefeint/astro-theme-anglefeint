# Visual Systems

Homepage switches in `src/site.config.ts`: `theme.home.showInitialize` controls the Initialize/done sequence, `showFollow` controls Wake Up/Follow, and `showTrace` controls the lower-right terminal status. All default to `true`; set each to `false` to hide it independently. The adapter maps these flags to `THEME.HOME`. Explicit startup/message CSS classes avoid selector ambiguity when one sequence is absent. With startup disabled, Wake Up begins immediately and Follow retains its relative pause. No dynamic JavaScript character/width calculation or client-side switch logic is added; the fixed text retains CSS width/steps animations. Disabled sections are omitted during Astro rendering, so their text and cursor animations do not exist in the generated page. These switches do not disable the background rain, mirror or rabbit effects.

## Article mathematics

Global mathematics is enabled in the current starter. `packages/theme/src/styles/math.css` imports bundled KaTeX styles/fonts and inherits article text color. Display formulas own horizontal overflow within the prose width; inline formulas remain inline. The BlogPost head includes the stylesheet only when the math adapter is enabled, with false fallback for old adapters. No canvas/background effect or article width contract changes. HTML plus MathML preserves accessible output; formula subtrees are excluded only from Pagefind, not accessibility. Nine-language browser checks cover 320, 390, 721 and 1440 px widths. Formula syntax, disabled-state MDX behavior and migration are user-guide concerns, not additional visual toggles.

This theme uses four distinct atmospheres by route.

## Nine-language layout validation

The built-in locales use horizontal LTR. Narrow article panels include padding and borders in their width, long prose paths can wrap, and inactive link-preview pseudo-elements do not create horizontal overflow. These local layout fixes retain the scene effects. New-language browser coverage exercises Home, Blog, About and article pages at 1280, 390 and 320 pixels.

## Reading-panel width caps

Above 720px, Home reserves its existing two 2rem paddings and two 1px borders in `max-width`; article prose reserves its two 2em paddings and borders. Both keep their 720px content-width cap on wide screens. Existing <=720px rules, cinematic effects and animations are unchanged; no global overflow clipping is introduced. The nine-language browser regression covers Home and a representative article at 320/390/720/721/740/768/800/820/900/1440px and asserts the wide-screen content width.

## Shared social menus

Optional `theme.footer.links` renders a separate row between copyright and theme credits, with explicit decorative dot separators and wrapping links. It defaults to empty and is independent of social menus and the credits visibility switch. Labels retain configured text across locales. The demo uses it for repository links, while its social icons point to account profiles.

Optional per-link `rel` changes static anchor semantics only; it does not affect colors, layout or interaction. No platform automatically receives `me`, and both new-window protection tokens remain present.

The shared footer groups copyright, optional localized theme/Astro credits and optional custom `site.tagline` separately, with social icons below. Content is capped at 720px; credits and custom text use smaller type, wrap on narrow screens and inherit the scene's chrome palette. Empty text and disabled credits do not reserve a row. The existing global tagline/environment override stays unchanged across languages; only built-in credits follow the page locale via `ThemeFrame` and the existing messages resolver. The legacy `Built with Astro.` tagline is still suppressed to avoid duplicate credits. No new client script or configuration field is needed.

Header and footer use the same configured order. The twelve built-in SVGs retain `currentColor` and existing menu hover colors; custom images use a fixed square box with `object-fit: contain` and retain source colors. Text-only links have readable line height and wrap. Footer menus wrap. Header menus stay in one horizontally scrollable row so fixed headers do not grow over page content; desktop headers with four or more links allocate remaining space to the controls. Keyboard links have a visible focus outline and can scroll into view. Header social links remain hidden at <=720px; footer links remain available. Empty configuration keeps three non-interactive placeholders. This does not alter the four scene effects.

## Design Intent and Change Principles

The product positioning is defined in [AGENTS.md](../AGENTS.md#product-identity-and-design-intent): lightweight, simple publishing with conspicuous cinematic character. The following describes creative intent; the route sections below describe implemented behavior.

| Atmosphere | Creative reference                          | Identity to preserve                                                                             |
| ---------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Matrix     | Matrix films                                | Green code rain, luminous terminal text and the sense of entering a digital world                |
| Cyberpunk  | Cyberpunk cinema, particularly Blade Runner | Clearly visible rain, sweeping light beams, halos, neon and Japanese night-market/street imagery |
| Hacker     | Hacker culture                              | Terminal typography, commands, files and tool-like interactions                                  |
| AI         | AI-product interfaces                       | Network visuals, monitors, system feedback and a futuristic reading environment                  |

The four scenes should remain distinct while sharing usable navigation and publishing features. Film-like impact is a core reason to choose this theme. "More cool" should mean stronger scene identity, expressive light/motion and cohesive interaction, rather than automatically making all effects quieter.

- Treat cyber rain, light beams and neon as signature scene elements. Do not reduce their visibility as a generic polish pass. The historical CSS explicitly names Blade Runner and describes its rain as dirty white rather than amber or cold cyan.
- Keep lightweight implementation and strong visual presence as simultaneous goals. Prefer efficient rendering, bounded resources and appropriate lifecycle management over erasing the visual identity. Do not assume an effect is expensive without checking its implementation or measuring it.
- Resolve concrete reading or interaction problems locally. Preserve accessible controls, mobile usability and reduced-motion alternatives; strong default atmosphere does not require forcing motion on every visitor.
- Compare visual changes in motion, including mobile, since a still screenshot cannot establish rain density, sweep timing or flicker rhythm. Explain any deliberate reduction in a signature effect before treating it as an improvement.
- Keep configuration and setup straightforward. Creative references guide design; they do not require adding every referenced motif, film asset or a new dependency.

### Shared numeric reveal configuration and Decoder SEO

The same `scripts/decoder/controller.js` serves About’s quick dialog and the standalone page. It computes the real decoded result before decorating it. `scripts/effects/numeric-reveal.js` owns one bounded Canvas and its cleanup; `numeric-reveal-timing.js` owns duration selection. The compatibility `decoder/timing.js` export delegates to that timing helper. Neither host borrows the terminal’s frame loop.

```js
createNumericReveal({
  target: resultElement,
  clock,
  durationRangeMs: [1500, 3000],
  inputLength: source.length,
  fadeMs: 1200,
  color: '#35e76c',
  highlight: '#72ff91',
  opacityRange: [0.7, 1],
  trailOpacity: 0.16,
  signal,
});
```

`durationRangeMs` is total milliseconds, including the final fade. Each play samples the range; inputs of at most 128 code units use its first 20%, up to 2048 use 20–60%, and larger inputs use 60–100%. Defaults therefore yield 1500–1800ms, 1800–2400ms and 2400–3000ms. `durationMs` explicitly overrides the range. Range endpoints are normalized and capped at 10000ms; equal endpoints select a fixed time. `fadeMs` defaults to 1200ms and is capped at 2000ms or the total duration, whichever is shorter. Original result and numeric overlay crossfade on the same frame subscription; scrolling, reduced motion, cancellation and disposal retain their immediate completion/cleanup behavior.

`color` and `highlight` default to Matrix green. `opacityRange` defaults to [0.7, 1], and `trailOpacity` to 0.16; opacity values are clamped to [0, 1]. Font size is optional (13px default, bounded to 8–24px). The controller reads host CSS properties once per submission and passes resolved values into the shared effect:

| CSS property                                                    | Decoder Lab                               | About dialog    |
| --------------------------------------------------------------- | ----------------------------------------- | --------------- |
| `--numeric-reveal-color`                                        | `currentColor`, resolved from result text | `#efbd66`       |
| `--numeric-reveal-highlight`                                    | `currentColor`, same result text          | `#ffda93`       |
| `--numeric-reveal-opacity-min` / `--numeric-reveal-opacity-max` | 1 / 1                                     | default 0.7 / 1 |
| `--numeric-reveal-trail-opacity`                                | 0 (no displaced impression)               | default 0.16    |

Lab result text uses `--lab-result: #78dcb2`. The Lab has no independent bright-white highlight or phosphor trail; only the final crossfade changes overlay opacity. About keeps amber/pale-gold digits and its default phosphor treatment. These CSS properties belong to the page skins; they are not new site-config fields. Even with the same color, Canvas glyph rasterization and the 13px numeric font can look different from result text.

On fine-pointer hover-capable devices, folder copy icons appear only while their card is hovered or contains keyboard focus. Touch/coarse-pointer devices retain visible icons. Native tooltips and accessible names use the localized “Copy article title” message.

### Read-only virtual terminal commands

The background terminal accepts a JSON descriptor (`terminal.entries` plus an initial `cwd` and localized labels), generated from the existing localized article collection and About configuration. Its initial working directory follows `about.scriptsPath`. `terminal/filesystem.js` normalizes virtual paths and synthesizes parent directories; `commands.js` tokenizes quoted/escaped arguments; `session.js` implements only `help`, `clear`, `pwd`, `ls` (optional `-l`/`-a`/`-la`), `cd` (including `cd ..`/`cd..`), `cat`, `vi`/`vim`/`view`. Unsupported commands do not execute JavaScript, processes or writes. Unique paths complete with Tab; Up/Down recalls bounded history. `cat` reads plain file contents, not copies. `vi` opens a read-only source-text view drawn in the original Canvas; `:q` + Enter or Escape returns to the same terminal transcript and directory. This is a small viewing mode, not a complete Vim editor.

`terminal/controller.js` owns input, bounded transcript and cursor lifecycle, with injected command/completion/wheel-policy callbacks. `renderer.js` owns wrapping and visible-row drawing; layout is cached between blinks. Transcript storage is capped at 500 raw lines/64 Ki UTF-16 units with a 4096-unit per-line cap. Wheel scrollback is active only over the focused background; foreground controls retain their wheel behavior. The terminal has no permanent rAF loop. `reader.js` owns pure reading state and exit commands. The same renderer draws the title, wrapped body, page position and command line; wheel, touch, arrows and PageUp/PageDown scroll visible rows. Wrapping is cached until content or dimensions change. An optional mode callback lets the host elevate the existing Canvas while reading; no reader modal or visible document DOM is created.

`terminal/loader.js` loads same-origin static JSON only when cat/vi needs a non-inline file, caps each body at 262144 UTF-16 units, and keeps at most four bodies (1 Mi UTF-16 units) in the page lifetime cache. Its stream has a byte cap, requests use AbortSignal, and disposal drops the cache. `src/pages/[lang]/terminal/[id].json.ts` emits per-article source-text JSON only when About is enabled, using the same locale collection and stable document identifier as the About manifest. No server runtime, external API, terminal package or user filesystem access is required. Startup article bodies are not embedded in the About HTML; the small configured About profile is inline. Command errors/help, reader hints and copy tooltips use the built-in locale registry with normal fallback/overrides.

Folder copy icon hover has no border or filled background; it moves down 1px, and active press moves down 2px. Keyboard focus keeps its visible outline.

The terminal controller optionally accepts a native `inputElement` and bounded accessible `outputElement`. TerminalBackdrop can render these controls when `inputLabel` is supplied. About activates the native input on background click; IME/paste/touch keyboards update the same Canvas input buffer, and a localized label plus a capped text log provide assistive access. Visual CRT layers remain aria-hidden.

Interactive About startup reads its JSON manifest, then runs real `pwd` through the same session/controller API as user commands. It no longer displays decorative directory listings, fake totals, permissions or file names from the old background banner. `effects.backgroundLines` remains available only to a non-session decorative host; the interactive session starts with its localized hint and actual current path. File listing appears only after a user command such as `ls`. No article-body fetch is needed for boot.

About audio panel transparency uses 25%–38% opacity in its gradient and a 10% title-bar tint, retaining 3px blur and unchanged foreground control/text opacity.
