- [GitHub Release](https://github.com/anglefeint/astro-theme-anglefeint/releases/tag/v0.10.0). The tag identifies the npm source; documentation closeout follows on main.

## Changes

- Configure one top-level `analytics.googleAnalyticsId` in `src/site.config.ts`; omitted/empty is off. Use the Web stream Measurement ID (`G-...`), not a property name or numeric ID.
- Cover all languages and shared themed layouts through ThemeFrame, without SEO or route edits. Static redirect documents are not tracked.
- Validate ID format; include the loader only in production builds. Skip localhost, `.localhost`, loopback and `0.0.0.0` previews. Remote/LAN previews still track.
- Queue one automatic page-view configuration and load the official Google script asynchronously. Preserve existing consent commands/dataLayer. No manual duplicate page_view, new runtime dependency, consent banner or automatic Consent Mode setup.
- Document setup, duplicate-installation precautions, consent responsibility and preview behavior in all nine READMEs.

## Upgrade

The complete feature needs the matching starter schema, defaults and theme adapter. npm alone does not update these files. Follow [UPGRADING.md](../../UPGRADING.md) and migrate content/personal settings into a fresh matching starter for the supported baseline. The `^0.9.x` range does not include `0.10.0`. No article or page-route changes are required.

Leave the ID empty until ready to enable collection. Rebuild and redeploy after changing it; visit the production site and check GA4 Realtime. Arrange any required consent management first, and avoid tracking the same site twice through GTM, Zaraz or a separate snippet. Real GA ingestion requires the user's own property and is not established by mocked/local tests.
