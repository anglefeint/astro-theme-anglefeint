## Changes and upgrade

Social links accept optional `rel: 'me'` or multiple space-separated values such as `'me nofollow'`. No platform/domain/icon automatically receives an identity relation. Omitted/blank values retain `noopener noreferrer`; configured tokens are lowercased, deduplicated and merged with these protections, while conflicting `opener` is ignored. Non-string values fail with an indexed configuration error. Built-in icons, custom local images and text links share the same static header/footer output. No arbitrary HTML attribute entry point, dependency, client script or visual change is introduced.

This additive public configuration capability is a minor release. Matching 0.11.x starters import the package's SocialLink type and pass entries through unchanged, so no schema/adapter migration is needed. An existing `^0.11.x` range will not select 0.12.0 automatically:

```bash
npm install @anglefeint/astro-theme@^0.12.0
npm run doctor
npm run preview
```

Redeploy after validation. Earlier migration requirements remain in [UPGRADING.md](../../UPGRADING.md).

Use `me` only for your own identity. For [Mastodon verification](https://docs.joinmastodon.org/user/profile/#link-verification), publish the website and save its HTTPS URL in your Mastodon profile fields. The target page must contain the backlink to your profile in HTML. Use the actual homepage (for example `/en/`) when `/` is only a meta-refresh page. The theme supplies markup; it does not guarantee network reachability or a Mastodon verification result. Nine READMEs and the package README document these boundaries.
