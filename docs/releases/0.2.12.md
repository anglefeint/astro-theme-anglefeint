# Release Notes: 0.2.12

## Package Changes

- Post scaffolding executes the actual TypeScript site configuration using Jiti, including imports and normalized language defaults.
- Invalid configuration reports an error instead of silently creating English posts. Explicit locale overrides remain independent of configuration loading.
- Existing posts are not overwritten; missing locale arguments fail clearly.
- Reduced-motion mode hides the animated side monitor without loading its playlist.
- Package exports include the configuration loader used by installed-project adapter checks.

## Starter Delivery

- Starter scripts/dependencies are generated explicitly without workspace or maintainer hooks.
- Managed output includes root routing, sitemap configuration, content schema, CJK metrics and required support scripts.
- Adapter checks execute real installed-package configuration. Known legacy patterns have read-only diagnostics.
- Windows content cleanup and push retries are corrected; source/main sync targets are rejected.
- Starter sync is required after npm publication. New users should use the latest `#starter` template.

## Existing Projects

For the complete updated skeleton, create the latest template in a new directory, then migrate articles, assets and personal settings. Keep the old project until the new one is verified. Do not replace new config helpers or lockfiles wholesale with old copies. See `UPGRADING.md`.

Compatible package-only updates remain possible, but this release does not guarantee automatic in-place migration of every historical starter. npm updates do not modify project-owned files.

## Verified Results

Acceptance environment: Windows, Node.js 24.14.1, 2026-09-10.

- Before publication: lint, 35 unit/integration tests, Astro check (123 files; no errors/warnings/hints), 91-page main build and five About runtime checks passed.
- Four independent installed-package builds passed: English/Chinese defaults and always/never default-locale prefix modes. Four desktop/mobile Playwright tests and release dry-run passed.
- Two remote starter projects were created using `npm create astro@latest`, then installed separately with npm and pnpm 10.34.5. Each passed 22 command checks and 26 HTTP route checks, plus preview sitemap access.
- Commands covered post/page scaffolding, all five locales/page themes, duplicate rejection, explicit locales, adapters, doctor/check, build, dev and preview. Desktop/mobile (1440px/390px) home/article checks had no page JavaScript errors; the reduced-motion monitor was hidden.
- All acceptance servers were stopped and both temporary projects deleted. Functional checks are not a security audit.

Create a new user project from the generated starter, not GitHub's main-source archive:

```bash
npm create astro@latest -- --template anglefeint/astro-theme-anglefeint#starter
```

For pnpm, skip template dependency installation, enter the generated directory, then run `pnpm install` with pnpm 10.

## Closeout and Limitations

- Closeout verification on 2026-09-11: 40 tests, clean lint, full check/build (126 checked files; 91 pages; five About pages) and the four installed-starter builds passed. Live registry verification recovered from two connection resets and downloaded the original package with matching SHA-1. Repeating publish dry-run for already-published 0.2.12 was rejected by npm's existing-version check; this is not recorded as a passing closeout dry-run and no publication was retried.
- Initial starter sync hit registry propagation delay (`ETARGET`). It succeeded after registry availability; the version was not republished. Subsequent maintainer tooling adds bounded dist-tag/tarball verification, README Markdown/HTML link validation, and explicit GitHub closeout steps. These maintainer/doc changes do not alter the published 0.2.12 package.
- Direct `pnpm create astro@latest` failed locally before template copying: pnpm 11.19.0 reported missing `@astrojs/cli-kit`; pnpm 10.34.5 reported a missing importer manifest in its dlx cache. Root cause remains unresolved. npm creation followed by pnpm 10 installation/commands passed; do not generalize this to all pnpm-create environments.
- The npm acceptance template reported 16 dependency audit findings (1 low, 2 moderate, 12 high, 1 critical). These remain a separate assessment/remediation task; no forced dependency upgrades were applied.
- Minimum Node 22.12, other operating systems, yarn/bun and historical starter in-place upgrades were not tested. Fresh-template migration is the supported baseline for skeleton changes.
- npm repository/homepage/bugs metadata is deferred to the next package release, not a reason to republish this version.

For project-owned file changes, migrate content and personal settings deliberately as described in `UPGRADING.md`.
