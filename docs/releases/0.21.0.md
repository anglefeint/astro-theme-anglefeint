# 0.21.0 — Machine-readable articles and compact publishing layouts

## Status

Release preparation on main, 2026-11-03. npm publication, starter delivery and GitHub Release are not yet complete. Exact source/starter revisions and delivery evidence will be added after verification.

## Changes

- Package-owned build integration uses Turndown/GFM and HTML parsing to export only rendered public article content. It writes root/language llms indexes, per-language full-text bundles and per-article Markdown companions, then adds discovery links to article HTML. Existing site identity, language and URL settings are reused; there is no new required configuration, API key, remote conversion service or production server.
- Whitelisted public metadata, noindex/off-site-canonical exclusions, absolute links/images, code fences/languages, tables, rendered MDX prose and KaTeX TeX annotations. Local ownership manifests prevent silent user-file overwrites and clean stale generated files on non-clean rebuilds. UTF-8 BOMs keep Chinese and other non-ASCII text readable when static hosts omit charset headers.
- Article prose no longer depends on JavaScript scroll-reveal classes. Title/date/context precede the compact framed cover; OUTPUT groups statistics with labels before values, tags sit between OUTPUT and prose, and Related aligns with the outer reading panel. The desktop content cap is 780px within the retained 802px panel.
- The first blog card uses a desktop 3:1 cover, left-aligned compact title/date and tighter spacing. All posts/Tags buttons on blog indexes become a compact right-aligned Tags shortcut. Nine shared neon palettes supply per-load article tag colors and pagination modes; the shortcut resamples every three seconds without immediate repetition, interpolates over 1.5 seconds and pauses while hovered/focused, hidden or reduced motion is enabled. Hover/focus uses a small scale and same-color glow.
- Four unbranded local WebP covers join the existing twelve. New-post uses Node crypto randomness once per invocation, writes the image into frontmatter and shares it across newly generated language files. Existing posts are not overwritten.
- Maintainer instructions clarify that optional local screenshot/appearance review needs user consent; ordinary requested edits, functional tests and release checks continue directly.

## Migration

Security remediation updates Satori from 0.32.0 to 0.33.5 and supplies root fflate 0.7.5 overrides in main and starter because upstream Satori pins 0.7.3. Existing consumers must merge the documented root override; installed-package overrides cannot enforce a consumer policy. Main keeps a matching Satori root anchor to resolve the workspace graph correctly. Scoped maintainer ESLint overrides use Minimatch 11.0.4; compatible lockfile updates include fast-uri 3.1.9, Zod 4.6.7, Undici 8.12.3/7.30.1 and Wrangler 4.156.2. Root audit reports zero findings after remediation. No forced audit fix or advisory exception is used. See [Satori escaping advisory](https://github.com/advisories/GHSA-wx4j-mvgx-mqwp), [fflate advisory](https://github.com/advisories/GHSA-px8p-9vwx-vf98) and [Minimatch advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249).

Use the matching starter or deliberately update project-owned `astro.config.mjs` with the machine-readable integration and existing site title/description. Remove the old `public/llms.txt` placeholder after preserving any custom guidance; conflicting user files are not overwritten. Package updates alone cannot edit this project configuration. Upload all of dist as usual. Machine exports are available after build/preview; dev does not advertise unbuilt companions. Site-search exclusions do not imply Markdown-export exclusions. See [UPGRADING](../../UPGRADING.md#0210-automatic-machine-readable-articles).

Starter synchronization is required for Astro config, documentation, removal of the placeholder and four local cover assets. No site schema or adapter field is added.

## Validation and privacy

Before release preparation, main checks passed 136 unit tests, zero Astro diagnostics, 199 built pages and nine About payloads. Exported output contained 126 article companions, nine language indexes and nine full-text bundles. The measured export stage took approximately 0.9–1.0 seconds. Functional Chromium checks passed JavaScript-disabled prose reading and Chinese UTF-8 text decoding, with no screenshots. Actual output links resolved and the reviewed text contained no placeholder site URL or local workstation paths. Nine-language README and upgrade/architecture references are synchronized.

Dependency remediation has passed root audit and Lint. Formal release gates, isolated installation/build-matrix results, registry/source verification and live deployment results remain pending. No full dry-run is required before the formal entry; no audit finding is waived.
