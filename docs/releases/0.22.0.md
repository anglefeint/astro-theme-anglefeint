# 0.22.0 — Configurable AI-readable site context

## Status

Release preparation on main, 2026-11-03. Publication and starter delivery remain pending; exact revisions and actual delivery results will be recorded after verification.

## Changes

Optional `aiReadableContent.notes` (Markdown) and `aiReadableContent.links` (`{ label, href }[]`) in `src/site.config.ts` supplement automatic exports. Each field can be overridden at `i18n.locales.<code>.aiReadableContent`; omitted fields inherit the global value, while empty notes/arrays suppress it. There is no policy translation or normal UI-message fallback. The root index uses global values; language indexes, full-text bundles and individual article companions use the corresponding locale values. No configuration preserves the previous output.

Single-article context is appended after a separator and site-context comment, separately headed from the article and its frontmatter. Full-text bundles include the context once. Standard Markdown link/image/reference destinations become absolute using Astro site/base; leading slashes resolve from the origin root. Code examples and surrounding authored text are preserved. Raw HTML is retained as authored and must use absolute attribute URLs. Configured destinations require HTTP(S) without URL credentials; targets are not fetched. No browser code or network conversion service is added. The template does not prescribe a content license or guarantee compliance by agents/crawlers.

## Migration and starter

The matching starter carries the new config/schema and Astro integration wiring. Existing projects must deliberately pass `aiReadableContent: THEME_CONFIG.aiReadableContent` and `locales: THEME_CONFIG.i18n.locales` to the build integration; installing the package alone cannot edit project-owned configuration. The draft name `machineReadable` was never published as a configuration key and is not retained as an alias. The integration import/module name remains `machine-readable`. See [configuration and migration](../../UPGRADING.md#optional-machine-readable-context).

Starter synchronization is required. Existing manifest-owned configuration files and the package's `src/machine` directory already cover the affected files; no new starter-owned destination is introduced. Nine-language README guidance is synchronized; historical release notes remain unchanged.

## Validation and privacy

Local validation passed 138 unit tests, Lint, documentation metadata, scaffold/adapter/pack checks, zero Astro diagnostics and a 199-page build, exporting 126 articles in nine languages. Tests cover field-wise fallback/clearing, root and locale outputs, single-article separation, once-only bundle notes, reference/image/nested links, code preservation and invalid configuration/destinations. Public-template acceptance now explicitly checks custom global/localized notes through the installed package and delivered integration. Formal audits, fourteen-build matrix, registry/source verification and remote/live delivery results remain pending.

No full dry-run precedes the formal release entry. Existing audits and release gates remain enabled. Audit evidence stays in ignored `acceptance-results/`; privacy reports redact findings rather than publishing account metadata. Cloudflare dashboard branch controls are not directly reinspected in this run; final GitHub build status and full live main inventory will be checked, without claiming unseen settings were verified.
