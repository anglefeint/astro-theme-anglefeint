## Fix and migration

Change the default blog/tag page size from nine to ten in the project configuration defaults and package fallback. A full Cards page now contains one leading card and nine regular cards, filling three desktop rows. The final partial page still shows the remaining posts. List mode shares the same static pagination; visitor storage continues to save only the chosen view.

New projects created from the matching 0.24.1 starter already default to ten; no manual page-size setting is needed. Existing projects retain their own `src/site.config.defaults.ts`, which used nine in 0.24.0. Updating npm alone does not replace that file, even when the author has never explicitly configured a page size.

For an existing project already using the matching 0.24.0 routes:

1. Install the patch with `npm install @anglefeint/astro-theme@0.24.1`.
2. In `src/site.config.ts`, add or change `blogPageSize: 10` inside the existing `theme` object passed to `defineThemeConfig`. Preserve all other settings; do not replace the configuration file. This explicit value overrides the old project default of nine.

   ```ts
   theme: {
     // Keep your other theme settings here.
     blogPageSize: 10,
   },
   ```

3. Run `npm run doctor` (the matching starter includes checks and a build), then `npm run preview` to inspect the result. Deploy the complete rebuilt output so blog and tag page boundaries move together.

This patch requires no additional schema, adapter or route changes **when upgrading from the matching 0.24.0 starter**. Older projects still need the [0.24.0 route migration](https://github.com/anglefeint/astro-theme-anglefeint/blob/main/UPGRADING.md#0240-archive-views-and-homepage-counts), or a fresh starter with deliberate migration of content/configuration. Old/customized projects may have different scripts. Authors who intentionally choose another page size may keep it; ten is the default for completing three desktop card rows, not a new restriction.
