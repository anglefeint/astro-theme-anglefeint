# 0.25.0 — Article authors and section links

## Status

Published npm `@anglefeint/astro-theme@0.25.0` from exact source `362978499b77958b07da1a01efeddd57c0345ccb`. Delivered starter `7f1510c1b80b9b6dd0000cbfe569a62ca8464e42` declares `^0.25.0` and resolves 0.25.0. Registry/source verification and fresh public-template acceptance passed. Final main references are recorded in the GitHub Release body.

## Changes

Article metadata shows a localized author byline beside the date, using a trimmed frontmatter `author` or the configured site author. When the resulting name matches the site author and About is enabled, the byline links to the localized About page and BlogPosting.author receives the same absolute URL. Other names remain plain text, and disabling About omits both links. No social accounts, credentials or additional identity claims are inferred. Hover uses bold, a 1.06 scale and soft cyan text glow without the generic prose link's rectangular glow or glitch; keyboard focus keeps an outline.

Body H2/H3 headings gain section-link copy icons using existing Astro heading IDs. The copied URL uses the article canonical address without tracking query parameters and adds the heading fragment. Icons appear on hover/focus and remain visible on coarse pointers. Success appears inline to the right; clipboard failures expose a selected read-only address for manual copying. Section controls are excluded from generic domain-preview tooltips. Without JavaScript, native TOC anchors remain usable. The existing effect lifecycle owns listeners, nodes and timers; no frame loop or dependency is added.

## Upgrade from the matching 0.24.1 starter

Run `npm install @anglefeint/astro-theme@0.25.0`, then `npm run doctor` and `npm run preview`; deploy the complete rebuilt output. Merge into the existing project rather than replacing configuration. No new schema, adapter, project route or mandatory configuration is required. Existing optional article `author` values remain supported. Older projects must still complete their earlier route/integration migrations described in [UPGRADING](../../UPGRADING.md).
