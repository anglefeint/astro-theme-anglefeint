# 0.27.0 — Integration starter (breaking)

## Status

Release authorized on 2026-11-09, prepared from main `90202476c1ad7c23887dd75d5b46832acd143f38`. Package version: 0.27.0. Publication, starter delivery, registry/source verification, remote installation/upgrade acceptance and GitHub Release closeout are in progress; no completed remote step is claimed here until verified. This supersedes the earlier unpublished starter-only SEO proposal.

## Changes

The package owns standard Home/Blog/article/Tags/About/Decoder/RSS/robots/terminal routes, configuration defaults/schema/normalization and derived i18n/config, internal fonts, CyberAtmosphere and build integrations. The existing page/effect composition is relocated, preserving cinematic parameters, feature gates, URLs, content and reduced-motion/lifecycle behavior. The main demo's user-config values, articles and public media remain intact. Existing pending LangSwitcher font-size/line-height edits predate this architecture task and were retained rather than redesigned.

The thin starter retains a short Astro entry, content/schema/type entrypoints, neutral site-config values, user guidance and content resources. It no longer distributes standard-page or generated-adapter implementation copies. The maintained manifest includes all sample-referenced covers so a clean starter can build without relying on residual files from an old distribution branch. Root legacy adapter fixtures remain only for maintainer diagnostics, not consumer runtime ownership.

`npx @anglefeint/astro-theme@latest upgrade` is the future published entry; the package's matching `astro-theme` bin implements it. For projectSchema 1 npm projects, it validates target/schema/Node/Astro compatibility, resolves an exact version, backs up dependency files, installs with lifecycle scripts disabled and runs doctor. User source/config/music/images/custom pages/host rules are not rewritten. Failed validation restores dependency files and attempts prior-dependency reinstall, reporting incomplete recovery and backup location if needed. `--check` is readonly for project files; `--to` selects a version. Old skeletons, unknown schemas, unsupported package-manager lockfiles and incompatible runtime requirements stop before dependency updates. The tool does not deploy or push. Cross-schema automatic migration is not implemented.

Article sitemap lastmod follows rendered updatedDate/pubDate, never build/file time. Terminal JSON retains its URL/body while route and generated static header metadata declare noindex. The build merges terminal rules into dist/_headers without rewriting public/_headers. Cloudflare Pages/compatible hosts apply them; other hosts require equivalent rules. The package's About validator rejects virtual terminal paths in URL attributes. No fake routes, tag-page removal or blanket redirects are introduced to reduce Search Console counts.

## Migration

Pre-0.27 projects intentionally require a one-time fresh-starter migration after delivery. Back up the old project; move articles, resources, music/images, personal configuration values and hosting settings into a new starter separately. Change local helper imports to the package config API. Preserve slugs/locales/resource URLs and explicit preferences. Do not copy old standard routes, generated adapters or helper implementations over the new skeleton. See [the migration guide](../../UPGRADING.md#0270-integration-starter-breaking-not-yet-published). Deep custom replacement pages need deliberate adaptation; use configuration/CSS/custom-page boundaries to keep future upgrades straightforward.
