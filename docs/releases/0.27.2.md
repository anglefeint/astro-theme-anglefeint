# 0.27.2 — Complete search-index output before finishing builds

## Status

Release preparation authorized on 2026-11-10. Publication, generated starter delivery, remote acceptance and GitHub Release are pending. Do not treat local implementation validation as registry or production delivery evidence.

## Changes

Fix an intermittent search build failure: Pagefind 1.5.2's native writeFiles can return while Tokio writes are still pending, so immediately reading pagefind-entry.json can see an empty file. Four isolated processes reproduced 13 early empty reads in 400 calls; every affected file became valid on a later read. This is a completion-boundary race, not a reason to reduce test concurrency.

The theme integration uses Pagefind's supported getFiles API to receive complete file buffers, parses metadata from those bytes, and awaits Node writes of all files before writing the theme language manifest and completing the build hook. No Pagefind fork, node_modules patch, monkey patch, private API, retry, sleep or empty-index fallback is introduced. Native errors or invalid metadata still fail the build. Search filtering, empty/disabled behavior, formats, URLs, styles and browser code remain unchanged. Complete buffers temporarily occupy build memory proportional to the index bundle; deployed browser payload is unchanged.

## Upgrade

For project-schema-1 npm integration starters, run from the project directory:

```sh
npx @anglefeint/astro-theme@latest upgrade
```

To select this exact patch, add `--to 0.27.2`. The updater preserves source/config/articles/music/images/custom pages, backs up dependency files and runs doctor; deployment remains separate. Failed dependency rollback does not restore dist/: resolve the failure and complete doctor successfully before deployment.

With pnpm, review compatibility and run `pnpm add @anglefeint/astro-theme@0.27.2`, then `pnpm run doctor`. The automatic updater remains npm-only. No configuration or content migration is required from the 0.27 integration starter. Pre-0.27 copied skeletons still need the [one-time migration](../../UPGRADING.md#0270-integration-starter-breaking-not-yet-published).

## Implementation validation already completed

These Windows/local results precede formal publication and are reused only where the runtime source has not changed:

- Fixed boundary: four processes, 400 real Pagefind indexing calls, zero early empty reads. The normal default-parallel 153-test suite passed ten consecutive runs with no skipped assertions or CPU restriction.
- Regression tests require complete binary files to be readable immediately on return, forbid the native disk API at the handoff, and reject native errors/missing/corrupt metadata. Real nonempty/empty/disabled indexing remains covered.
- Main full check: 344 Astro files with zero diagnostics, 262 pages and nine About payload checks. Lint passed.
- Actual isolated tarball installation: 14 build variants and blocking audit passed, zero known vulnerabilities.
- Full functional Chromium suite: 139/139 passed in 5.1 minutes. No optional appearance review was performed.
- Frozen schema-1 real-command upgrade to unpublished fixture 0.29.0: five scenarios passed and all 85 user files were byte-preserved. This is a local skipped-version simulation, not a published upgrade.

Evidence is retained under ignored acceptance-results/: pagefind-race-summary.json, pagefind-suite-1.log through -10.log, pagefind-fixed-check.log, pagefind-installed.log, pagefind-e2e.log and upgrade-1794243975534/report.json.
