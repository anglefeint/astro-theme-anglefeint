# 0.28.0 — Optional shared Giscus comments

## Delivery status

Release preparation only. npm publication, starter delivery, remote acceptance and the GitHub Release are pending. Do not treat local validation as registry or live-site verification. Source/starter commits will be recorded after delivery.

## Changes

- Add optional theme.comments.shareAcrossLocales, default false. Existing comments remain disabled unless configured; ordinary pathname/custom mappings and default fixed English interface language retain their prior behavior.
- Shared mode uses the complete article slug without its locale, preserving directories, as the per-article Giscus specific term with strict matching. Nine translations with the same slug share one GitHub Discussion and reactions. Different slugs remain separate. Comments are not translated.
- Validate conflicts instead of silently replacing custom mapping/term/number/strict settings. Enabled shared comments without a valid article slug fail clearly. Custom BlogPost consumers must provide articleSlug in this mode.
- Separate comments configuration into User Guide 4 in all nine demo/starter languages; retain Guide 3 URLs and link to the new article. Include ordinary/shared setup, diagnostics and restoration instructions.
- Continue using Giscus's official public client script. No dependency-source edits, private API calls, discussion merges/deletions or updater writes to personal configuration are introduced.

## Upgrade and opt in

For npm schema-1 integration starters, upgrade from the blog directory:

```sh
npx @anglefeint/astro-theme@latest upgrade
```

Use --to 0.28.0 to select this version. No configuration edits are required to keep existing comment associations. The updater preserves source, configuration, articles, music/images and custom pages, backs up dependency files and runs doctor. Preview/deployment remain separate.

To opt in, keep your enabled/repository/category values and merge these fields into theme.comments in src/site.config.ts:

```ts
shareAcrossLocales: true,
mapping: 'specific',
term: '',
number: '',
strict: '1',
lang: '',
```

The article supplies term dynamically; do not put one global term here. lang: empty follows the page language, while an explicit language remains fixed. Conflicting configuration fails when comments are enabled. Matching translation slugs are required, for example cypherpunk-ideals-ai-and-the-future-of-crypto. guides/setup and other/setup remain distinct.

Existing discussions and historical comments are not automatically combined, moved or deleted. Opting in may associate a different discussion without the old comments. Save the original mapping/term/number/strict values before switching. To restore the original association, disable shareAcrossLocales and restore those exact values. Any historical migration is a separate, deliberate manual GitHub operation.

With pnpm, install @anglefeint/astro-theme@0.28.0 and run pnpm run doctor; the automatic updater remains npm-only. Pre-0.27 copied skeletons require the [fresh-starter migration](../../UPGRADING.md#0270-integration-starter-breaking-not-yet-published). This optional feature is not a project-schema break.
