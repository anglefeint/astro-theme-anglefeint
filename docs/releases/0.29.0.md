# 0.29.0 — Optional Fragments

## Delivery status

Release preparation authorized. npm publication, starter delivery, remote acceptance and GitHub announcement remain pending until recorded below. The repository version is 0.29.0; this preparation is not proof of registry availability.

## Changes

- Optional localized Fragments feeds render user-owned Markdown from `src/content/fragments/<locale>/`. Feed and comments default off; pageSize defaults to 20 (1–100). The demo enables the feed and keeps its comments off after local review.
- `new-fragment` creates default-language Markdown with a stable UUID and timestamp; explicit enabled locales share an ID without automatic translation. IDs survive filename changes. There is no draft or future-date publication filter.
- Articles and fragment popups reuse `Giscus.astro`, configuration resolution and the same official client.js. No Giscus npm dependency or alternate comment service is introduced. One popup client/iframe survives closing and switches discussion targets using `fragment/<id>` with strict matching and the page language. Existing article mapping remains unchanged.
- Popup comments are independently enabled and reuse existing repository/category settings. Readiness, errors, 15-second timeout, retry, focus/scroll restoration and stale-response isolation are handled by the theme. No GitHub discussions are merged, deleted or migrated.
- Nine-language User Guide 5, Guide 2 links and starter guidance describe configuration, static publishing and comment setup. User articles, fragments, configuration, media and custom pages remain outside updater writes.
- Maintainer lockfile refresh resolves the upstream fast-xml-parser advisory through a compatible release; no dependency source modifications or audit exemptions.

## Upgrade

For npm schema-1 integration starters:

```sh
npx @anglefeint/astro-theme@latest upgrade
```

Use `--to 0.29.0` for this exact version. Existing projects need no new scripts: `npx @anglefeint/astro-theme@latest new-fragment` works after availability. New starters also supply `npm run new-fragment`. Merge `fragments: { enabled: true }` into the existing theme object to opt in; enable its comments separately only after configuring Giscus. Rebuild and deploy after editing Markdown/configuration. Personal tutorial copies are not overwritten.

The automatic updater remains npm-only and project schema stays 1. Pre-0.27 copied skeletons require the [fresh-starter migration](../../UPGRADING.md#0270-integration-starter-breaking-not-yet-published). See [upgrade details](../../UPGRADING.md#0290--optional-fragments).

New blog:

```sh
npm create astro@latest -- my-blog --template anglefeint/astro-theme-anglefeint#starter --no-install --no-ai
cd my-blog
npm install
npm run dev
```

GitHub source archives contain maintainer main source; use the public starter command for a personal blog.
