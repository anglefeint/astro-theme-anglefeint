# 0.33.0 — Default sharing artwork and short Fragment IDs

Status: local preparation; not yet published or synced. Source baseline: `4a0b9f03820b4964ebf5a67146f643c5e42b347b`.

## Changes

- Bundle the approved 1200×630 Anglefeint OG artwork and optional `site.ogImage` public-root/HTTPS override. Explicit page/article images, generated article cards and disabled-generation heroes retain priority; Fragment hash links share feed metadata. Local custom image URLs change with their bytes; missing files fail the build.
- Generate eight-character case-sensitive alphanumeric Nano IDs, checking existing Markdown IDs across languages and retrying collisions before writing quoted YAML. All translations share one ID/time. Only eight alphanumeric ID characters are accepted. All demo identities are reset across nine languages; old IDs/links/comments are not bridged.
- Nano ID 5 preserves the existing Node range (including odd Node releases); js-yaml is explicitly declared for CLI frontmatter parsing. Neither enters browser code. Assets/helper ship inside existing package ownership; no new starter-managed implementation is needed.
- Nine-language README and demo/starter Guides 1 and 5, npm README and upgrade/reference documentation synchronized.

## Upgrade and validation

Use the normal [schema-1 npm upgrade](../../UPGRADING.md#0330-default-sharing-artwork-and-short-fragment-ids) after publication. Delete/repost existing long-ID fragments before upgrading; the new strict format rejects them. New IDs change links/comment association; old GitHub discussions remain. No migration or legacy-compatibility tool is added.

Local functional browser regression passed 238/238 cases (single-worker run, 7.1 minutes), including short-ID sharing, pagination, comments, nine-language metadata and the existing visual/runtime behavior. Targeted CLI/index tests passed 8/8; nine-language render fixtures passed default/local/HTTPS OG selection, missing-file failures and strict-ID rendering. The real isolated upgrade passed under the strict-ID contract (`acceptance-results/upgrade-1794425088840/report.json`), retaining user files while exercising the future localized page/menu/component/client fixture. A pre-steering run with the earlier long-ID contract is not counted as current acceptance.

All 117 demo files were compared with the source baseline: body and metadata other than ID are unchanged; thirteen new shared IDs span nine languages. Global format, lint and document metadata checks pass. Evidence: `acceptance-results/0330-demo-content-preservation.json`, `release-0330-browser.log`, `release-0330-final-unit.log`, `0330-strict-render.log` and `release-0330-strict-upgrade.log`.

Actual npm/source/starter refs and results will be recorded after execution. Remaining gates: protected main checks, default release entry with independent installed-package/audit matrix, fresh remote npm/pnpm template acceptance and production verification. All default release gates remain; no validation-result caching or routine duplicated dry-run.
