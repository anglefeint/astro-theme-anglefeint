# 0.33.0 — Default sharing artwork and short Fragment IDs

Status: npm 0.33.0 published and download-verified; starter delivered and fresh remote/production acceptance passed. Source-tag/GitHub closeout is linked below. Source baseline: `4a0b9f03820b4964ebf5a67146f643c5e42b347b`; actual npm source: `1d658303952f3de280f178c196679e72bef6e248`.

## Changes

- Bundle the approved 1200×630 Anglefeint OG artwork and optional `site.ogImage` public-root/HTTPS override. Explicit page/article images, generated article cards and disabled-generation heroes retain priority; Fragment hash links share feed metadata. Local custom image URLs change with their bytes; missing files fail the build.
- Generate eight-character case-sensitive alphanumeric Nano IDs, checking existing Markdown IDs across languages and retrying collisions before writing quoted YAML. All translations share one ID/time. Only eight alphanumeric ID characters are accepted. All demo identities are reset across nine languages; old IDs/links/comments are not bridged.
- Nano ID 5 preserves the existing Node range (including odd Node releases); js-yaml is explicitly declared for CLI frontmatter parsing. Neither enters browser code. Assets/helper ship inside existing package ownership; no new starter-managed implementation is needed.
- Nine-language README and demo/starter Guides 1 and 5, npm README and upgrade/reference documentation synchronized.

## npm delivery and post-upload documentation correction

The single default `release:npm` invocation passed main checks (178 tests, 289 pages and nine About assertions), zero-vulnerability audits and all fourteen independent installed builds, then uploaded once. npm accepted publication, but its registry processing exceeded the automatic 121.8-second verification window. Standalone read-only `release:verify --version 0.33.0 --source 1d658303952f3de280f178c196679e72bef6e248 --shasum 003595ec0fe88ab33db4d8a4426dc149af269965` subsequently passed tag, metadata and exact download identity. No second upload occurred; starter was held until this succeeded. Evidence: `acceptance-results/maintainer-1794425678688-21220-SMv4bj/` and `release-0330-registry-recovery.log`.

The optional OG configuration example was initially written as a standalone `site: { ... }` fragment. Prettier interpreted it as TypeScript labels and inserted a semicolon that cannot be copied into an object. Corrected all 46 source examples to a complete configuration call before delivering starter/online tutorials:

```ts
export const THEME_CONFIG = defineThemeConfig({
  site: { ogImage: '/images/share.jpg' },
});
```

Merge this property into existing settings rather than replacing them. Runtime code is unaffected. The immutable 0.33.0 npm README/source archive retains the original example; the current repository and delivered tutorials contain the correction. Following the maintainer docs-only policy, this correction is not a second npm publication or a moved source tag; a future package release will carry the corrected npm README. The GitHub announcement includes this valid example and links current guidance.
