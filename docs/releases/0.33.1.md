# 0.33.1 — Direct Fragment anchors and release tools

Status: local preparation; npm, starter, remote-template and production delivery pending. Source baseline: `f49219bd12acc057097d8a80630c11e56ff51082`.

## Changes

- Share Fragments as `/<locale>/fragments/#ID`, using the existing eight-character case-sensitive alphanumeric ID directly. Date links, native card anchors, clipboard/manual fallback and off-page redirects agree. Per-language versioned JSON indexes, comment terms and IDs remain unchanged. No detail route or new dependency. Old `#fragment-ID` links are not aliases; recopy links after deployment.
- Update nine-language README, npm README and nine pairs each of demo/starter Guides 1 and 5. Existing personal tutorial copies remain user-owned.
- Separate npm release operations into maintainer-only tools with a machine-readable catalog, read-only plans and explicit execution. Dependencies execute once in a composed invocation. Default checks, audits, installed matrix, upload and download verification remain; legacy `release:npm` calls the same operations with its existing options.
- Agent workflow chooses capabilities under safety/completion constraints; six reporting phases replace forty manual actions. Standalone starter/browser/upgrade/consumer/recovery commands remain discoverable. No historical-result cache, pre-push bypass, altered consumer command coverage or single-artifact publishing claim.

## Validation and delivery

Local checks: 238 full browser cases passed (4.6 minutes), plus 23 focused Fragment cases (13.7 seconds). Real local upgrade 0.33.1 to fixture 0.35.0 passed with protected files unchanged (`acceptance-results/upgrade-1794428894502/report.json`). Six tool tests cover real operation adapters, blocking audits/installed build flags, dependency ordering/deduplication, invalid plans, failure-before-upload, verification-without-republication and read-only discovery/planning. Lint, global formatting and metadata validation passed.

The first browser attempts failed because the sandbox used a different browser cache and denied loopback networking; using the installed browser cache and authorized unsandboxed functional tests resolved that environment failure. An initial adapter test mock returned an invalid registry response; it was corrected and rerun, without any real upload. Concurrent documentation discovery also scanned transient test Markdown; the standalone post-cleanup check passed. These failures remain in local diagnostic evidence and are not counted as passed attempts.

Formal npm/source/starter/remote-template/production delivery is pending. Record actual refs, package identity, final results and limitations as they complete.
