# 0.33.2 — Shared back-to-top control

Status: npm 0.33.2 published once and exact-download verified; starter delivered and its installed-package doctor/build passed. The [GitHub Release](https://github.com/anglefeint/astro-theme-anglefeint/releases/tag/v0.33.2) records final refs and closeout timing. Demo regression remains user-owned.

## Changes

- Articles and Fragments share BackToTop.astro, its stylesheet and a small lifecycle-managed controller. Fragments uses feed positioning and existing localized labels. Visibility starts after 400px; hidden controls leave the tab order. Reduced motion uses immediate scrolling. No dependency or animation loop is added. Article progress and TOC/music positioning remain page-owned.
- Nine-language README, npm README and demo/starter Guide 5 explain the automatic control. npm schema-1 users upgrade the package and redeploy; no configuration/content migration. Personal tutorial copies remain user-owned.
- Maintainer validation tools are independent and explicitly selected. Unconditional full pre-push checking is removed; staged checks, blocking audits, one upload, exact registry download verification and starter doctor remain. No historical-result cache. Consumer doctor and upgrade remain unchanged.

## Selected technical evidence and completion

The selected plan covers focused release-planner/recovery/doctor/starter units, back-to-top lifecycle/reduced-motion units, nine-language static Fragment rendering, Astro diagnostics, lint, document metadata/formatting and one independently installed default build. Publication includes blocking source dependency audit, packed-content checks, npm identity and exact-version/tag/download verification. Starter delivery retains installation, audit and one doctor/build, followed by source-tag and GitHub Release read-back. Actual results belong in the linked GitHub Release and ignored acceptance-results receipts, including failures and any read-only recovery.

Browser regression (including targeted cases), screenshots/visual measurements, Cloudflare account/settings/build polling, live demo inventories/tutorial comparisons and real Giscus checks are deliberately not executed. Demo regression belongs to the user and does not block npm/starter completion. No complete source-check, all-unit suite or fourteen-configuration matrix is selected. See the validation policy for the explicit-consent boundary.

Timing separates implementation/document preparation from the formal release window, with individual selected-tool, registry propagation and starter delivery durations. Avoiding duplicate invocations does not claim historical result reuse.
