# 0.35.0: Homepage Matrix Fragments and avatar reactions

Status: preparing; npm publication, starter delivery and source tag/GitHub Release are pending. This record describes the intended release; actual refs and checks are filled after execution. The [documentation audit](../CODE_DOC_AUDIT.md#2026-11-13-homepage-fragments-avatar-archives-and-article-presentation-local) covers implementation and publication-surface review.

## User-visible changes

- Enabled, nonempty localized Fragments gain an initially closed homepage avatar entrance below the header. The independent Matrix window previews the latest three notes using bounded text, the first valid image and the first code block. Full-card links preserve stable feed IDs; the single bottom count/arrow links to the complete feed. Preview cards have equal clipped heights; complete feed cards retain natural heights and gain larger spacing. No heading, fake signal bars or redundant per-card arrows are added.
- The original pixel character keeps its typing/headphone/code-rain GIF. The eagerly decoded reaction strip stops typing, straightens, turns and smiles through its eyes. One stepped Web Animation plays forward on hover/focus and reverses from the current pose on exit before restoring typing. Quick re-entry preserves progress; reduced motion uses the still. Original, mirrored and forward/reverse exported artwork remains archived; runtime does not request a second reverse GIF.
- Article OUTPUT keeps words, estimated tokens and the optional model label. Reading time, latency and confidence are no longer displayed, including explicit overrides, while existing frontmatter fields and metric-helper compatibility remain. Article/title/body opacity entrances and prose breathing/scaling are removed. Background network and title light effects remain.
- Scope homepage terminal list arrows to main content so they do not leak into music playlists. Fragment close/focus state is independent of the music player. Add 24 bilingual demo case pairs covering local images, code, long content and pagination; these are not consumer starter samples or browser acceptance evidence.

## Compatibility and distribution

No new configuration, dependency or content migration is required. The existing `theme.fragments.enabled` switch remains off by default; empty/disabled collections omit the homepage entrance. Package-owned components, scripts, styles, utilities and runtime artwork ship through existing file patterns. Source artwork archives and demo cases stay outside npm runtime/starter distribution. Nine README translations, npm README and nine demo/starter pairs each of Guides 2/5 are synchronized through their existing manifest ownership. Personal content, images, music, configuration and tutorial copies remain user-owned.

Supported npm schema-1 projects can use the [normal upgrade procedure](../../UPGRADING.md#0350-homepage-fragment-previews-and-article-presentation) after publication. Pre-0.27 copied skeletons retain the documented fresh-starter migration boundary. Rebuild and redeploy to apply presentation changes; Fragment IDs, sharing and comment associations are preserved.
