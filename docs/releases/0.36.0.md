# 0.36.0: Persistent responsive images and immediate About reading

Delivery status and exact npm/source/starter/tag identities are maintained in the [GitHub Release](https://github.com/anglefeint/astro-theme-anglefeint/releases/tag/v0.36.0) and its closeout receipts. This ledger describes the release source, compatibility and selected pre-publication checks; it is not a deployment or PageSpeed measurement. Demo/visual acceptance remains user-owned.

## Changes

- Blog List/tag archives, article main covers and local Fragment images share persistent WebP width variants and SHA-256 validity checks. Dev and local doctor prepare missing/stale files; builds/config sync/CI doctor validate and copy committed bytes without deployment-cache dependence. Keep originals and existing paths. Archive covers prioritize two candidates; article covers stay eager/high and their Canvas reuses the selected DOM image instead of requesting the original separately.
- Markdown, reference-style and HTML Fragment image links support relative sources and public root paths. Fill missing dimensions, preserve explicit dimensions, prioritize the first feed image and lazy-load the remainder. Homepage previews share the same responsive candidates. SVG/animation retain formats; remote images retain original URLs. Only actual rendered formulas cause math CSS on the current article/feed page.
- About text and window chrome appear immediately. Controls enable after binding; section-title typing reserves full text geometry. Oracle passage/font and decoder styles/controller load on interaction, with retry and close/switch/disposal guards. Share DecoderForm without pulling standalone background/styles into About startup. Preserve terminal/background/light-band visuals and reduced motion.
- Separate image source inspection, compiler adaptation and HTML rendering. One integration owns its cached manifest snapshot; pages do not import the scanner/compiler. Shared image selection/types avoid duplicate rules. Synchronize nine-language README/npm README and relevant Guides 2/5 through the existing starter manifest; personal tutorial copies are not overwritten.

## Compatibility and upgrade

No new dependency, site-config field or project schema is required. Use the supported npm schema-1 [upgrade procedure](../../UPGRADING.md#0360-persistent-responsive-content-images). Existing local doctor prepares derivatives before its unchanged checks. Keep original images plus all of `src/assets/blog/covers/` (`manifest.json` and `generated/`) in Git before deployment. A missing/stale/corrupt file stops build/CI doctor with the preparation command; deployment never repairs it. The existing command is `npx @anglefeint/astro-theme prepare-covers`, with `--check` for read-only validation. Custom source/public directories should prepare via configured dev; see [asset boundaries and troubleshooting](../BLOG_COVER_ASSETS.md).

WebP quality 80/resizing is lossy; widths are bounded at 1200px. Originals remain unchanged. This pipeline covers the listed image paths, not every media asset. Unreferenced old variants are not deleted automatically. Pre-0.27 copied skeletons retain the deliberate fresh-starter migration boundary. Rebuild and deploy the complete static output, including `_blog-covers`.
