# 0.36.1: Runtime reliability and multilingual publishing guides

Delivery status, exact source/npm/starter/tag identities, technical outcomes and measured stage timings belong in the [GitHub Release](https://github.com/anglefeint/astro-theme-anglefeint/releases/tag/v0.36.1) and ignored maintainer-session/closeout evidence. This source ledger defines the candidate and validation scope; it does not claim publication or demo acceptance before delivery completes.

## Changes

- Normalize article authors consistently for bylines and generated social-image keys, including empty and padded values.
- Pass the Fragments switch through dev, build and CLI image preparation. Disabled Fragment references are skipped; article cover references and the two cover-source pools still participate. Do not delete originals or existing derivatives.
- Release Red Queen verification/playback decoders and stale decoded frames, bound failing decode/fallback retries, and preserve normal playback timing and artwork.
- Validate `theme.blogPageSize` as a positive safe integer while preserving the default 10. Allow failed homepage corridor imports to retry without disturbing later activations.
- Respond to live reduced-motion changes through an article-owned motion lifecycle, preserving reading controls and normal visual effects. Build a locale/translation index once per article-path generation, preserving related-post order and language/SEO behavior without cross-build caching.
- Refresh nine-language READMEs, eight task-based tutorials and fourteen configuration-reference articles per language. Preserve default commands and link to matching localized demo guides. Explain the 0.36.1/0.36.0 behavior boundary explicitly.
- Retain ten concise entry/design articles per language. Turn welcome into the tutorial/reference entry point, remove inaccurate manual counts, and delete the redundant upgrade-model, Hello World and community-manifesto demo articles. Their old URLs are no longer generated; retained slugs and image assets stay unchanged. Starter includes only its manifest-owned welcome/tutorial/reference set, not all demo design articles.

## Compatibility and upgrade

No dependency, configuration field, project schema or default publishing workflow changes. Supported npm schema-1 projects use the existing `npx @anglefeint/astro-theme@latest upgrade` command, then rebuild and deploy. Invalid existing `blogPageSize` values must be corrected; valid positive safe integers continue working.

User articles, config, media, custom pages and existing tutorial copies remain user-owned. Updating the npm package does not overwrite personal README/tutorial content. New starter output contains the refreshed localized material. Pre-0.27 copied skeletons retain the fresh-starter migration boundary. Persistent image preparation and deployment ownership remain as documented for 0.36.0.

## Selected technical delivery plan

Run focused author/path/locale/SEO, motion, decoder, retry, pagination, Fragment-image and starter tests; types, lint, workspace/integration/packed-CLI checks; one main build; document/link checks and formatting after fixture cleanup. Select one independent packed installation/audit/CLI check. The starter delivery separately retains its installed audit and doctor/build, plus restoration of main dependencies.

The source handoff retains normal commit hooks, structured starter drift preflight, main push and one npm upload with exact metadata/tag/download verification. Closeout creates and reads back the exact-source tag and GitHub Release. Stage/session clocks distinguish command duration, operation time, explicit registry retry sleep and coordination. Record external agent/tool intervals separately; do not infer propagation time from generic network latency.

No full source aggregate, fourteen-case matrix, browser/screenshot, Cloudflare/deployment polling, public-demo inventory or real Giscus check is selected. Demo acceptance remains user-owned. An accepted npm upload is never repeated; availability recovery is read-only.
