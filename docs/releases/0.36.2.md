# 0.36.2: Automatic build images and localized publishing examples

Delivery status, exact source/npm/starter/tag identities, technical outcomes and stage timings belong in the [GitHub Release](https://github.com/anglefeint/astro-theme-anglefeint/releases/tag/v0.36.2) and ignored maintainer-session/closeout evidence. This ledger defines the candidate and selected checks; it does not claim publication or demo acceptance before delivery completes.

## Changes

- Normal dev, build and doctor (including CI) reuse valid persistent image derivatives and prepare missing, stale or corrupted ones. Blog covers and supported local Fragment images use the existing shared preparer. Explicit prepare-covers --check and configuration synchronization remain read-only.
- Preserve missing/invalid-original errors, manifest validation, path/output safety, original bytes, existing WebP dimensions/quality, vector/animation passthrough and disabled-Fragment isolation. No new image setting, directory, dependency or platform cache is needed.
- Use the default create-astro dependency-installation wizard in nine READMEs and installation tutorials. Run npm install separately only when installation was deliberately skipped; retain --no-ai, default languages, common CLI commands and preview images.
- Correct generic examples in all nine locales' eight tutorials and fourteen configuration-reference articles, including code, frontmatter, comments, alt text, environment/table examples and placeholders. Preserve deliberately demonstrated Chinese language configuration and real Chinese defaults. Synchronize starter templates and matching-language demo links.

## Compatibility and upgrade

Supported npm schema-1 projects use the existing npx @anglefeint/astro-theme@latest upgrade flow, then build and redeploy. No schema/configuration migration is required. Automatic build/CI preparation starts in 0.36.2; 0.36.1 needs prior dev or prepare-covers preparation. Commit originals; committing generated assets/manifest remains recommended for reuse, but normal builds can create them. Original-source and safety failures are not hidden by cached derivatives.

Personal content/configuration/media/custom pages and existing README/tutorial copies remain user-owned. The npm updater does not replace personal documentation. Refreshed examples reach new starter projects and the demo through the starter/main sources. Pre-0.27 copied skeletons keep their fresh-starter migration boundary.

## Selected technical delivery plan

Reuse this task's passing evidence for unchanged implementation: 13 image/CLI tests, types (0 errors/0 warnings, two existing hints), one 471-page main build and targeted lint. The 19-test combined run included six tutorial/starter tests; repeat only those six after release-version wording changes. Existing evidence also covers 576 TypeScript examples, 6,126 article links/anchors, nine preserved README preview-image counts and repository formatting. Metadata/format changes remain covered by normal commit hooks.

The source handoff performs a fresh virtual starter static check, the selected six documentation/starter tests, required registry/version/authentication checks, blocking main audit and packing. It retains normal commit hooks, structured starter drift preflight, push/source confirmation, a single upload and exact tag/metadata/download verification. Starter delivery independently installs the actual published package in its isolated worktree and retains its audit, doctor/build and commit hooks; no additional installed matrix or duplicate main build is selected.

Prepare and review closeout notes once, then create/read back the exact-source tag and GitHub Release. Session evidence distinguishes measured command/operation time, explicit registry retry sleep and coordination outside commands. No full source suite, browser/screenshot, Cloudflare polling, public-demo inventory or real Giscus check is selected. Demo acceptance remains user-owned; accepted npm uploads are never repeated.
