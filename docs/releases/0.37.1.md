# 0.37.1: Decoder semantics and Fragments anchor initialization

## Fixes

- Remove `aria-label` from the Decoder output's plain `pre`, whose implicit role prohibits that name. The enclosing result section retains its localized accessible name and the output remains keyboard focusable. Both the standalone Decoder page and About's shared form receive the fix; decoding and appearance are unchanged.
- Initialize Fragments navigation/title measurements before link positioning on initial load, Astro page-load and persisted pageshow. Existing measurements are reordered; no timer, wait, additional scrolling or visual change is introduced. Native `#ID` navigation and stable cross-page fragment lookup are preserved.

## Compatibility

No configuration, schema, content, dependency or migration change is required from 0.37.0. Astro peer support remains `^7.4.7`; the main/starter Astro target remains `^7.4.12`. User configuration, content, IDs, images and custom pages remain user-owned.

## Selected delivery plan

Run the focused Fragments chrome lifecycle unit file, types, one main build, packed-CLI checks, one independent installed-package check, formatting, document metadata and virtual starter checks. Retain blocking dependency audits, normal commit hooks, exact npm source/download verification and isolated starter install/doctor/build delivery. No browser regression, visual measurement, live Giscus or hosting acceptance is selected; the Lighthouse report identified the original ARIA finding but is not a retest of this fix.

Exact source/npm/starter identities, completed checks and timings belong in the [GitHub Release](https://github.com/anglefeint/astro-theme-anglefeint/releases/tag/v0.37.1) and ignored maintainer-session evidence. This plan does not claim delivery before execution.
