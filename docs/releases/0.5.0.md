# Release Notes: 0.5.0

## Changes

- Generate 1200×630 article share PNGs during the static build using Satori and Sharp. A complete bundled Noto CJK font supports the default Latin/CJK languages without downloading fonts during generation.
- Explicit article `ogImage` takes priority, independently of `heroImage`. Article-relative assets, public paths and HTTPS URLs are supported. Missing local images fail clearly. `theme.socialImage.enabled: false` disables generation while preserving manual images and the previous hero/default fallback.
- Generated image URLs depend on title, author, site, locale and template revision. Public custom images receive a byte-derived URL revision. OG, Twitter and article JSON-LD share the selected image.
- Simplify the header language selector to one visible border while retaining native selection and focus feedback.
- Exclude nested workspace dependencies from documentation discovery and synchronize the code-first documentation.

## Migration

The theme still requires Astro `^7.3.2`. This version adds an Astro integration and configuration contract: register `socialImage()` from `@anglefeint/astro-theme/social-image`, and use the matching config schema/defaults/theme adapter. Updating only the npm package in an older customized starter is insufficient. Prefer a fresh matching template and deliberately migrate content and personal configuration as described in [UPGRADING](../../UPGRADING.md).

```bash
npm create astro@latest -- --template anglefeint/astro-theme-anglefeint#starter
```

GitHub source archives contain main source, not the generated starter template.

## Limitations

- The complete font adds approximately 16.4 MB uncompressed to installation, not to article page font downloads. Image generation adds build time; no production image server or browser generation script is needed.
- Long titles are shortened only on the image. The SC font favors Simplified Chinese glyph forms; arbitrary emoji and writing systems outside the bundled font are not guaranteed.
- External platforms may cache previews; remote custom-image availability remains the owner's responsibility.
- Package-manager acceptance uses npm; pnpm/yarn/bun are not revalidated in this release.
