# 0.8.3 — Music seeking without HTTP Range

The player downloads the complete selected audio file and gives native Audio a Blob URL. This fixes seeking back to zero on the reproduced MP3/static-host combination that returns the full file instead of honoring Range requests. The existing controls, configuration and default-off behavior remain unchanged. No dependency or music asset is added.

Downloads remain lazy. Pause/resume reuses the pending download or loaded source; switching tracks and destroying the player abort obsolete downloads and revoke Blob URLs. Stale completions cannot start the wrong track. Failed downloads can be retried.

## Upgrade and hosting requirements

Matching 0.8.x starter projects can update the package with `npm update @anglefeint/astro-theme`, then run `npm run doctor`. No configuration, route or adapter migration is needed. Older projects must follow UPGRADING's baseline requirements.

**External audio hosts must now permit cross-origin fetch (CORS).** A URL that plays directly in a browser is not proof that it permits fetch from your site. Enable CORS on the audio host or move the file to the site's `public/music/` directory and configure `/music/file.mp3`. Same-origin files need no CORS configuration. Sites with a custom Content Security Policy must permit the audio source in `connect-src` and `blob:` in `media-src`.

Playback waits for the entire file; larger files and slower connections increase startup latency and memory use. Navigation recreates the source, subject to browser HTTP caching, so session resume still has a gap and can require a click if autoplay is blocked. The player does not retain the whole playlist in memory. Five-language READMEs and User Guide 3 explain these requirements. Starter synchronization is required to deliver the updated guidance and dependency range/lockfile.

## Validation and delivery

- Local implementation checks passed: 61 unit tests, lint, documentation metadata, adapter/scaffold/package CLI checks, Astro diagnostics and a complete static build. Astro reported five informational hints in ignored diagnostic scripts, with no errors or warnings.
- Chromium tested real pointer/drag/paused/compact seeking with generated audio served as HTTP 200 without Range support, navigation resume, manual pause, blocked playback in five languages, mobile/storage denial and missing sources. Unit tests cover download cancellation, stale results, Blob revocation and retry.
- An isolated comparison used the same 13,478,182-byte MP3 as the reported issue. Against a server ignoring Range, direct native Audio returned to zero after seeking to 180 seconds; the updated core reached 180.01 seconds with a seekable range covering the full 336.927-second track.
- Release gates and public delivery are pending. This record will be completed after registry verification and remote starter acceptance.
- Browser verification is Chromium only; Safari/Firefox and subjective listening were not tested. External hosts must meet the CORS requirement above.
