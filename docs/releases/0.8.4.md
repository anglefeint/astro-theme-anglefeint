# 0.8.4 — Article translation metadata

Articles with missing translations no longer advertise language-specific blog listings as alternate versions. The route supplies `seoLocaleHrefs` containing only enabled, existing same-slug translations, separately from the language menu's `localeHrefs`. The head uses it for hreflang and OG alternate locales. Without a default-language translation it omits `x-default`; canonical URLs and menu fallbacks retain their behavior.

## Upgrade

Requires theme 0.8.4 and the matching starter article route. Existing Astro 7.3.2-compatible 0.8.x projects can merge the change to `src/pages/[lang]/blog/[...slug].astro` after upgrading the package, preserving customizations. Routes without the new optional prop retain legacy metadata behavior. See [UPGRADING](../../UPGRADING.md). No author configuration, content migration or additional dependency is introduced. Blog-list pagination is outside this fix.

New projects use:

```bash
npm create astro@latest -- --template anglefeint/astro-theme-anglefeint#starter
```
