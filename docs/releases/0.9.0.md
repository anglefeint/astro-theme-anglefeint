# 0.9.0 — Nine built-in languages (unreleased)

## Status

Implementation is local and publication is pending. The npm package version remains 0.8.5 until release preparation can proceed. No 0.9.0 tag, npm publication or public starter delivery has occurred.

The 2026-10-03 main and independent installed-starter dependency audits are blocked by `http-cache-semantics@4.2.0`, through Astro. [GHSA-ch52-4w7c-c8xp](https://github.com/advisories/GHSA-ch52-4w7c-c8xp) affects versions through 4.2.0; the registry currently offers no patched version. Astro 7.3.5 still declares `^4.2.0`. The project release gate requires a clean audit; no force downgrade, audit suppression or dependency override was introduced. This advisory does not establish that this static site exposes the shared-cache scenario described in the advisory.

## Changes

- Add Brazilian Portuguese (`pt-br`), German (`de`), Russian (`ru`) and Traditional Chinese (`zh-hant`) alongside the original five defaults. English remains the default; existing route keys remain unchanged.
- Supply complete message dictionaries, new-post skeletons, localized neutral About content, demo introductions, four README translations and fourteen translated demo articles per new language. The generated starter selects four articles per language, for 36 files; main has 126 articles.
- Use `pt-BR` / `zh-Hant` HTML and hreflang tags; retain lowercase route keys. HTML language now follows configured hreflang, including `zh-CN` for the existing `zh` route. Search indexes remain separated by page language.
- Map automatic Giscus language to `pt` and `zh-TW` for the new regional/script locales. Explicit comment-language configuration still takes priority.
- Keep horizontal LTR layout. Adapt narrow article panels and long text; prevent hidden link-preview boxes from widening the page. Signature visual effects are retained.
- Add translation-schema/placeholder coverage, locale configuration tests, new article inventory checks, share-image cases and browser tests for the four new locales.

## Migration

This upgrade requires matching starter configuration/content/docs as well as the package. An npm-only update provides package UI strings and scaffolds, but does not add languages to an existing starter's local registry or translate its content.

Once released, create the latest public starter in a new directory and migrate personal content/settings deliberately. Do not overwrite customized files or copy old configuration helpers over the new ones. All nine languages are initially enabled: disable unwanted languages with `meta.enabled: false`. Omitted overrides do not disable defaults, and the default locale remains enabled. The new-post command creates nine skeletons initially; it does not translate content. Existing article files are preserved.
