入門ガイドの第2 / 8回です。[全ガイドの順序](/ja/blog/starter-guide-1-configure-your-site/#tutorial-order) · [設定リファレンス](/ja/blog/config-reference/)。

[インストールとサイト設定](/ja/blog/starter-guide-1-configure-your-site/)が終わったら、普段の執筆では主に `src/content/blog/` 内の記事を編集します。タイトルや日付など記事ごとの情報は冒頭の frontmatter に記入し、サイト名、既定著者、全体のスイッチは `src/site.config.ts` で設定します。

まずプロジェクト既定の手順で記事を作成・プレビューし、必要に応じて言語を選びます。後半の項目一覧は必要なときに参照してください。

## 1. 既定の手順で記事を作る

`package.json` のあるプロジェクトルートで実行します。

```bash
npm run new-post -- my-first-post
```

第1回で実行済みなら、既存ファイルを開いて続けてください。同名ファイルはスキップされ、内容は上書きされません。

`--locales` と `ANGLEFEINT_LOCALES` が未指定の場合、有効な全言語に `src/content/blog/<locale>/my-first-post.md` を生成します。初期状態は9言語なので、9個のひな形ができます。言語を調整済みなら現在の有効リストを使います。本文の自動翻訳は行いません。

編集する言語のファイルを選びます。URL は `/<locale>/blog/my-first-post/`、一覧は `/<locale>/blog/` です。たとえば既定の英語では `/en/blog/my-first-post/`、簡体中国語では `/zh/blog/my-first-post/` です。それぞれの言語を有効にする必要があり、ルートの手動作成は不要です。

`my-first-post` は記事の slug です。`learning-astro-1` のように英小文字、数字、ハイフンだけを使い、空白、アンダースコア、`/` は使えません。記事ファイル名を変更すると URL も変わり、旧 URL のリダイレクトは自動作成されません。

コマンドはタイトル、説明、当日の UTC 日付、仮の本文を設定します。`src/assets/blog/default-covers/` に WebP・PNG・JPEG があれば1枚をランダムにカバーに選び、なければ `heroImage` を設定しません。カバーはダウンロードしません。生成後に文面、日付、画像を変更できます。

### 特定の言語だけに作成する場合

次は既定コマンドの選択肢です。簡体中国語のみなら zh、英語と簡体中国語なら en,zh を指定します。例をすべて順に実行する必要はありません。

```bash
# 簡体中国語だけを作成
npm run new-post -- my-first-post --locales zh

# 英語と簡体中国語を作成
npm run new-post -- my-first-post --locales en,zh
```

`--locales` を省略すると、`ANGLEFEINT_LOCALES` 環境変数があればそれを、なければプロジェクトの有効言語を使います。優先順位は `--locales` → `ANGLEFEINT_LOCALES` → 有効言語です。同じ実行で作った新規ファイルは選んだカバーを共有し、既存ファイルは変わりません。

ファイル作成だけを行い、自動翻訳も言語の自動有効化もしません。訳文は対応する言語ディレクトリに同じ slug で置きます。記事詳細の言語切り替えでは、同じ slug の翻訳があればその記事へ、なければ対象言語の記事一覧へ移動します。

## 2. タイトル、説明、日付を記入する

生成されたファイルを開きます。冒頭2本の `---` の間が YAML frontmatter、その後が本文です。まず次のように書けます。既存の `heroImage` は残して構いません。

```md
---
title: '最初の記事'
description: 'Anglefeint でブログを作る過程を記録します。'
pubDate: '2026-11-13'
tags: ['astro', 'メモ']
---

最初の記事です。学習の過程や出会った問題をここに記録します。

## ブログを始める理由

考えを書き留め、将来の自分への手がかりも残します。

### まず小さな問題から

今日はインストールと公開の手順を記録します。
```

日付は実際の公開日に変更します。`title`、`description`、`pubDate` は必須で、`tags` は任意です。タイトルはページ側が表示するため、本文は通常 `##` から始め、`# 最初の記事` を重ねて記入する必要はありません。

- `title` は記事タイトル、一覧、関連メタ情報に使います。
- `description` は記事の説明およびページのメタ説明です。`context` がなければタイトル直下のコンテキスト行にも表示します。
- `pubDate` で、新しい記事から古い記事への並び順を決めます。
- 公開記事を実質的に更新したら、実際の `updatedDate` を追加できます。更新日として表示し sitemap でも優先しますが、一覧順の `pubDate` は置き換えません。

日付は引用符付きの `YYYY-MM-DD` を推奨します。時刻が必要なら `'2026-11-13T09:00:00+08:00'` のようなタイムゾーン付き ISO 形式にします。記事ページは UTC 日付を表示するため、変換で日付が変わる場合があります。

**現在、下書きや予約公開を隠すフィルターはありません。** 他言語に生成したひな形もビルドで公開されます。公開前に必要な記事を完成し、未公開のファイルは `src/content/blog/` の外へ移してください。`draft: true`、未来の `pubDate`、`search: false` は非公開化の手段になりません。

## 3. 本文を書き、見出しで整理する

段落の間に空行を入れます。一般的な Markdown の例です。

```md
本文では **太字**、_強調_、`インラインコード`を使えます。

- 最初のポイント
- 次のポイント

[リンクのテキスト](https://example.com/)

> これは引用です。
```

`##` と `###` を使うと目次が自動生成されます。広い画面では本文右、狭い画面では本文前に表示し、レベル2・3の見出しがなければ表示しません。レベル4以降の見出しは本文で使えますが、この目次には入りません。

その記事だけ目次を使わない場合は、既存 frontmatter に追加します。

```yaml
toc: false
```

`toc` を省略すると `src/site.config.ts` の `theme.toc.enabled` を継承し、既定は有効です。`toc: true` は全体の無効設定を上書きできます。目次はコンパイラーの Markdown 見出しを使い、MDX コンポーネント内部や生の HTML/JSX の見出しは自動収集しません。

### タグで記事を整理する

frontmatter に `tags: ['astro', 'メモ']` を指定すると、タグの入口と現在の言語のタグ一覧を自動生成します。ルートの手動追加は不要です。タグが有効なら、たとえば簡体中国語の `/zh/tags/` にアクセスできます。

タグは大文字小文字を区別し、`Astro` と `astro` は別です。前後の空白は除去し、同じ記事の重複タグは1回だけ数えます。中国語や特殊文字には安定したエンコードを使うため、パスを推測せず生成済みリンクを使ってください。タグを改名すると対応するリンクも変わります。

`theme.tags.enabled: false` は全体のタグ入口とタグページの生成を止めますが、記事自体は残ります。

## 4. コードと数式を挿入する

コードブロックは3個のバッククォートで囲み、後ろに言語名を指定します。

````md
```js
const message = 'Hello, world!';
console.log(message);
```
````

記事本文のコードにはコピーボタンを自動追加し、改行とインデントを保持してコピーします。JavaScript のコードでも実行せず、テキストとしてコピーするだけです。クリップボードが使えない場合は失敗表示になり、手動で選択してコピーできます。ボタンには JavaScript が必要です。

数式は既定で有効で、プラグインの追加は不要です。インラインは `$...$`、独立した数式は2行の `$$` の間に記入します。

```md
節約量は $C_{saved}$。

$$
\frac{a}{b} = x_1 + x_2
$$
```

通常のドル記号が紛らわしい場合は `\$` と記述します。インラインコードとコードブロック内はそのままです。ビルド時に KaTeX で数式を描画するため、その数学構文に対応し、完全な LaTeX 文書ではありません。誤った数式はコンパイルまたはビルドを失敗させ、出典を表示します。長い独立数式は横スクロールできます。

全体で数式を止める場合、`src/site.config.ts` の既存 `theme` に `math: { enabled: false }` を統合します。タイトルと説明はプレーンテキストにし、その中で数式が描画されることを前提にしないでください。

### MDX を使うのはどんなとき？

通常の執筆は `.md` で十分です。記事内でコンポーネントを import して使いたい場合は `.mdx` を使えます。両拡張子を収集し、MDX でも数式に対応するため、別の処理系を追加する必要はありません。

`new-post` は `.md` を生成します。必要なら frontmatter を残して `.mdx` に変更できます。同じ言語と同じベース名の `.md` と `.mdx` を別記事として両方残すと同じ記事パスになるため避けてください。MDX のコンポーネントと式は MDX 構文に従う必要があり、拡張子だけを変えたプレーンテキストではありません。

## 5. 記事に画像を追加する

本文画像には記事の隣のファイルや `public/images/` のファイルを使えます。実ファイルを先に配置し、対応するパスを記入してください。

```md
![写真の内容を説明](./photo.jpg)

![写真の内容を説明](/images/photo.jpg)
```

1つ目は記事ファイルからの相対パス、2つ目は `public/images/photo.jpg` に対応し URL に `public` を含めません。説明は画像の代替テキストになります。

カバーを変えるには、記事の隣に `cover.jpg` を置いて frontmatter に `heroImage: ./cover.jpg` を設定します。`heroImage` はローカル画像に対応し、省略も可能です。本文画像、カバー、共有画像は用途が異なり、カバーを変えても本文には自動挿入されません。

通常の本文画像はクリック、またはフォーカスして Enter／スペースで拡大でき、Esc・閉じるボタン・背景で閉じます。カバーとリンク・ボタン内の画像は対象外です。ブラウザーが選択済みの画像ソースを使い、高解像度原画像の追加取得やアルバム切り替えはありません。

カバー追加・変更後はローカル dev または doctor がレスポンシブ画像を用意します。原画像と `src/assets/blog/covers/` 全体（manifest.json と generated/ を含む）をコミットしてください。通常の build と doctor は CI でも不足・期限切れ・破損した派生画像を補い、正しい既存資源は再利用します。原画像がない場合や不正なパスは引き続きエラーです。この永続派生規則はカバーと Fragments のローカル画像が対象で、通常の記事本文画像は既存の Markdown/MDX 処理を使います。

## 6. ローカルでプレビューして公開に備える

`npm run dev` を実行し、ターミナルの URL 配下の `/<locale>/blog/my-first-post/` を開きます。英語は `/en/blog/my-first-post/`、簡体中国語は `/zh/blog/my-first-post/` です。タイトル、日付、本文、目次、タグ、画像を確認し、翻訳を追加した場合は言語切り替え先も確認してください。

公開前に開発サーバーを停止して実行します。

```bash
npm run doctor
npm run preview
```

doctor は確認とビルドを含むため、成功直後に check や build を繰り返す必要はありません。preview はビルド済み `dist/` を表示し、サイトを公開しません。ビルドに失敗したら先に修正し、残存する成果物を配備しないでください。

### dev で記事を検索できないのはなぜ？

全文索引はビルド時に生成します。`npm run dev` の検索入口は開発用の案内を表示します。ビルド後の preview で本文の一節を検索し、検索全体と記事への移動を確認してください。

既定では現在の言語の記事タイトルと本文を検索します。特定の記事だけを検索対象から外すには frontmatter に `search: false` を追加し、省略すれば対象になります。これは一覧、RSS、sitemap、公開 URL への表示を止めません。全体の `theme.search.enabled: false` は検索入口と索引生成の両方を止めます。

オンライン検索を更新するには、記事変更後の再ビルド・再配備が必要です。数式や装飾 UI は検索本文に含めません。

型、既定値、現在使われない状態は[記事設定リファレンス](/ja/blog/config-article/#frontmatter)、検索独自の規則は[検索リファレンス](/ja/blog/config-search/#article-search)を参照してください。以下は執筆でよく使う項目の一覧です。

## 必要に応じて参照：その他の記事項目

すべて記事の frontmatter 項目であり、`src/site.config.ts` の `site` や `theme` には入れません。通常の記事で全部を指定する必要はありません。

### タイトル領域と画像

| 項目        | 現在の動作                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `subtitle`  | 任意の副題。コンテキスト行と同じ文面なら重複表示しません。                                                                                 |
| `context`   | タイトル下のコンテキスト行。未指定なら `description`、`''` なら非表示です。メタ説明は変えません。                                          |
| `author`    | 記事ごとの著者。未指定または空白だけならサイトの著者を使います。                                                                           |
| `heroImage` | 一覧と記事詳細のローカルカバー。省略可能です。                                                                                             |
| `ogImage`   | 自分で指定する共有画像。自動画像より優先し、記事からの相対画像、`/images/share.png` などの public パス、HTTPS の画像直リンクに対応します。 |

既定では `ogImage` がない記事に、タイトル・著者・サイト名を使った1200×630共有画像を生成します。本文のカバーは置き換えません。`theme.socialImage.enabled: false` で自動生成を止めても手動 `ogImage` は有効で、その他の記事はカバーやサイト既定画像にフォールバックします。変更後は再ビルドと再配備が必要で、共有サービス側に旧画像がキャッシュされる場合があります。

### OUTPUT の統計と任意の状態表示

| 項目                | 現在の動作                                                   |
| ------------------- | ------------------------------------------------------------ |
| `wordCount`         | 自動語数を上書きする非負整数。                               |
| `tokenCount`        | tokens の推定値を独立して上書きする非負整数。                |
| `aiModel`           | 記入したモデル名をタイトルの状態領域と OUTPUT に表示します。 |
| `aiMode`、`aiState` | 記入したモード・状態の文面をタイトルの状態領域に表示します。 |

未指定ならソース本文から語数を推定し、CJK の漢字・仮名・ハングルは1文字ずつ、それ以外は主に空白区切りで数えます。既定 tokens は `round(max(自動語数, 1) × 1.3)` で、実際のモデルのトークナイザーではありません。`wordCount` だけを変更しても tokens は再計算されず、必要なら別々に指定します。

一部の Markdown を除外しますが完全な表示文字数ではなく、数式や MDX ソースも影響します。1,000以上は小数1桁の `k` 表示です。モデル、モード、状態は文字列を表示するだけで、AI サービスへの接続、記事由来の検証、タスク実行は行いません。

### 互換用項目と現在表示に使わない項目

- `readMinutes`、`aiLatencyMs`、`aiConfidence`：旧記事のデータとして受け付けますが、現在の記事ページには読了時間・遅延・信頼度を表示しません。残す場合の型は順に正整数、非負整数、0–1の数値です。新規記事での記入は不要です。
- `canonicalTopic`：文字列を受け付けますが、現在はページ・canonical・エクスポートに接続されず、トピックの作成や記事 URL の変更は行いません。
- `sourceLinks`：HTTP(S) のソース URL 配列を受け付け、ドメインだけなら `https://` を補います。現在は検証だけで、参考リンク表示やエクスポート追加は行いません。読者に見せたい出典は本文に Markdown リンクで書いてください。

未対応の独自項目がページ機能になるわけではありません。たとえば `draft` に下書き動作はありません。上記の既存項目と本文の記法を優先してください。
