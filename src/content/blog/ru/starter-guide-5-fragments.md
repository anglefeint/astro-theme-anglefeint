## Контент, доступный для чтения ИИ

Сборка включает публичные статьи, включённые Fragments и About в `/llms.txt`, языковые индексы и полные тексты. Markdown-адреса статей не меняются. Для каждого языка создаются `/ru/fragments/index.md` и `/ru/about/index.md` (замените код языка). Fragments объединяет все публичные страницы, сохраняя ID, время публикации, текст и стабильные ссылки `/<locale>/fragments/#ID`. HTML содержит ссылку на Markdown. Файлы доступны после `npm run build` и в preview; публикуйте весь `dist/`.

About экспортирует публичную биографию, контакты и доступное текстовое окно AI, исключая настройки терминала, инструменты и декорации. Комментарии не экспортируются. Отключённые страницы/языки, удалённые записи, noindex и внешние canonical исключаются; пересборка удаляет устаревшие созданные файлы и ссылки. Пользовательские файлы защищены, конфликт останавливает сборку. Дополнения сайта/языка применяются ко всем документам. JSON-LD содержит язык; About использует AboutPage. Новые настройки, сервер или UI-библиотека не нужны; индексация и цитирование ИИ не гарантируются.

Начиная с 0.33.2, Fragments использует ту же кнопку возврата наверх, что и статьи: она появляется после прокрутки и учитывает настройку уменьшения движения. Дополнительная настройка не нужна.

Для существующего блога сначала обновите тему до 0.29.0 или новее:

```bash
npx @anglefeint/astro-theme@latest upgrade
```

Добавьте поля в существующий theme в `src/site.config.ts`. Фрагменты и комментарии по умолчанию выключены. Пункт меню расположен под Decoder Lab.

```ts
theme: {
  fragments: { enabled: true, pageSize: 20, comments: { enabled: false } },
},
```

После включения откройте `/<locale>/fragments/`. `pageSize` принимает целые числа от 1 до 100. Файлы используют `.md`; черновики и будущие даты не фильтруются. Храните ещё не опубликованные фрагменты вне `src/content/fragments/`.

Создайте заготовки одного фрагмента для всех включённых языков:

Создание заготовок для всех включённых языков по умолчанию требует темы 0.31.0 или новее. Сначала обновитесь; в 0.29–0.30 укажите `--locales` явно.

```bash
npx @anglefeint/astro-theme@latest new-fragment
```

Как и `new-post`, по умолчанию команда создаёт заготовки для всех включённых языков проекта с общими ID и отметкой времени; автоматического перевода нет. Приоритет: `--locales` → `ANGLEFEINT_LOCALES` → включённые языки. В явных списках удаляются пробелы и повторы, коды приводятся к нижнему регистру; конфигурация не загружается, создаются только указанные языковые папки, без включения языков в настройках.

В новых starter также есть `npm run new-fragment`; существующие проекты могут использовать npx без добавления скриптов.

```bash
npx @anglefeint/astro-theme@latest new-fragment --locales en,zh
npx @anglefeint/astro-theme@latest new-fragment --locales ru
```

Редактируйте Markdown в `src/content/fragments/<locale>/`. Заголовок необязателен:

Чтобы добавить перевод позже, скопируйте исходный Markdown в папку нужного языка, сохраните id и переведите текст.

```md
---
id: 'q8Lm3XzP'
pubDate: 2026-11-11T08:30:00+08:00
---

Фрагменты.
```

Сохраняйте id при правках и переименовании. Только переводы одного фрагмента используют общий ID. Дубликаты в одном языке вызывают ошибку сборки. pubDate содержит время и часовой пояс; показ в UTC, сначала новые записи.

Включите `theme.fragments.comments.enabled` и задайте repo, repoId, category, categoryId в `theme.comments` значениями Giscus. Настройка репозитория описана в руководстве 4. Комментарии статей можно оставить выключенными. [Giscus](https://giscus.app/) · [4](../starter-guide-4-giscus-comments/)

```ts
theme: {
  fragments: { enabled: true, comments: { enabled: true } },
  comments: {
    repo: 'yourname/your-repository',
    repoId: 'R_...',
    category: 'Your category',
    categoryId: 'DIC_...',
  },
},
```

Используются specific, строгое совпадение и `fragment/<id>`. mapping, term, number, shareAcrossLocales, lang статей не применяются; язык интерфейса следует странице. Переводы с одним ID делят комментарии и реакции. Связи обсуждений статей не меняются. Клиент комментариев загружается при первом нажатии. Закрытие скрывает диалог; повторное открытие или выбор другого фрагмента использует тот же экземпляр комментариев.

Fragments остаётся отдельно от поиска статей и RSS, но при сборке создаёт собственный Markdown для ИИ. Изображения из `public/images/` доступны через `/images/...`.

Обновите тему до 0.29.0 или новее и включите настройку. Личный контент, конфигурация, музыка и изображения сохраняются. Личные руководства не заменяются; смотрите актуальный demo. Обсуждения GitHub не объединяются и не удаляются.

Комментарии загружаются удалённо. Индикатор остаётся до готовности Giscus; при ошибке или через 15 секунд появляется повторная попытка. Проверьте сеть или настройки. Диалог использует ту же интеграцию Giscus, что и статьи; отдельный npm-пакет Giscus не нужен, а связи статей не меняются.

```bash
npm run build
```

Пагинация в версии 0.32.0 и новее: фрагменты используют те же номера страниц, неоновые стили и переход к странице по настроенному порогу, что и Blog. `theme.pagination` управляет обоими списками; `theme.fragments.pageSize` по-прежнему отдельно задаёт число фрагментов на странице.

## Стабильные ссылки для публикации (0.32.0+)

Ссылки в версии 0.32.0 и новее: дата ведёт к фрагменту в списке, рядом находится кнопка копирования. Используйте `/ru/fragments/#ID`, где ID — id из frontmatter Markdown. Только если фрагмента нет на текущей странице, загружается небольшой статический индекс языка для перехода на нужную страницу. После добавления записей, изменения дат или pageSize пересоберите сайт, сохраняя ID. Поиск между страницами и копирование требуют JavaScript.

Адрес в браузере может содержать номер страницы; для публикации используйте ссылку даты или кнопку копирования. Существующие старые страницы исправляют устаревший якорь, но удалённый номер страницы по-прежнему показывает обычную страницу 404. Эта функция не перехватывает 404.

Если фрагмент отсутствует или сеть недоступна, выводится сообщение без повторных переходов. При запрете доступа к буферу обмена появляется ссылка для ручного копирования. Для этой функции требуется тема 0.32.0 или новее; обновитесь перед использованием автоматического поиска.

## Изображение по умолчанию и короткие ID Fragment (0.33.0+)

Добавьте site.ogImage в существующий объект site файла src/site.config.ts. Поддерживается путь от public (/images/share.jpg соответствует public/images/share.jpg) или HTTPS URL. Пустое значение включает встроенное изображение Anglefeint 1200×630. Fragments и все ссылки #ID используют это изображение. Собственные и автоматически созданные изображения статей сохраняют приоритет; при отключённой генерации обложка статьи также важнее изображения сайта. После изменения пересоберите и разверните сайт; сервисы могут кэшировать предпросмотр.

```ts
export const THEME_CONFIG = defineThemeConfig({
  site: { ogImage: '/images/share.jpg' },
});
```

new-fragment создаёт Nano ID из восьми букв и цифр с учётом регистра, проверяет Markdown ID всех языков и повторяет при совпадении. Все языки запуска получают общий ID и время. Допустимы только восемь букв или цифр. Старые UUID и длинные ID не поддерживаются: удалите старые записи и опубликуйте заново. Миграции и совместимости старых ссылок нет. Сохраняйте новый опубликованный ID: изменение создаёт другую связь с комментариями.
